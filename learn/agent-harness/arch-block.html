Agent Harness Tutorial · Architecture

The harness: one block between the user and the model

A customer never talks to the model directly. Everything in between is the agent harness, and the concerns are what's inside it.

The demo is the model. The system is the harness. The harness decides what the model sees, which tools may touch the transaction systems, what it remembers, when a person must approve, what it must not do, what gets recorded, and how a change ships safely.

Click the dark block to open it: that is the end-to-end map, with every concern in the order one message meets it.

Sign-in, and one call to get a claim

Two things in the picture above deserve a closer look: how Rohan proves who he is (Microsoft Entra ID), and how that proof travels all the way to the claims system, so the harness can never fetch more than Rohan himself may see.

StepWhy it is done this way
PKCE, state and a nonce on sign-inStops a stolen code or a forged callback from signing someone in
Access token only in the page's memoryIt travels in the URL fragment, which browsers never send to a server, so it is in no access log
Refresh token encrypted in agent_state.sessionsIt never reaches the browser; the cookie only names the login. Unused for 12 hours, it is deleted
Customer id from the token, never from the message"I am PH-2002" in a message changes nothing
On-behalf-of token for the claims systemThe claims system sees Rohan, not a powerful service account, and checks again on its side
Rows filtered by the holder in the token"Not yours" looks exactly like "doesn't exist" (flow 14)

More: the front door, how the token is checked, the claims system checking again, flow 14: someone else's claim.

Want every detail? The long version is in the Series: sign-in, the token, and who may do what.

Code view: input, process, output, the call stack, the classes

Goes inA browser signing in, then each chat message's bearer token
What happensThe sign-in runs Entra's code flow with PKCE and a nonce and keeps the refresh token; each message's token is verified, and each tool call swaps it for a claims-system token on the customer's behalf
Comes outA verified Identity per message, and a far-end token per tool call

agent_harness/identity/entra.py:104Checking Rohan's token on every message
def verify_entra(
    token: str,
    *,
    issuer: Issuer,
    now: int | None = None,
    role_scopes: RoleScopes | None = None,
    holder_claim: str = CLAIM_CUSTOMER,
) -> Principal:
    """`identity.verify` for Entra's claims: the same signature check, issuer,
    audience and expiry (`decode`), the session named by `uti`, and an app role
    granting the scopes `role_scopes` gives it.

    `holder_claim` is where the customer id is read from. Entra writes a
    directory extension attribute as `extn.<name>` (claims-fnol-azure A2), not
    `customer_id`, so the overlay names it, and the far end reads the same name."""
    claims = decode(token, issuer=issuer, now=now, require=("uti",))
    party = claims.get("azp")
    return Principal(
        subject=str(claims["sub"]),
        customer_id=holder_of(claims.get(holder_claim)),
        scopes=frozenset(entra_scopes(claims, role_scopes)),
        session=str(claims["uti"]),
        party=party if isinstance(party, str) else None,
        token=token,
    )
agent_harness/identity/entra.py:179The on-behalf-of exchange: a token for the claims system, still Rohan's
    async def for_far_end(self, identity: Identity) -> str:
        if not identity.token:
            raise InvalidSession("no session to exchange")
        now = float(self._clock())
        cached = self._cache.get(identity.token)
        if cached is not None and cached[1] - 30 > now:
            return cached[0]
        body = await self._post(identity.token)
        token = body.get("access_token")
        if not isinstance(token, str) or not token:
            raise EntraMalformed("on-behalf-of answered 200 with no access_token")
        self._cache = {k: v for k, v in self._cache.items() if v[1] > now}
        self._cache[identity.token] = (token, now + float(body.get("expires_in", 60)))
        return token

@dataclass(frozen=True)
class _Gate:
    """Who is asking, and whether money may move: this system's checks."""

    store: Store
    authorise: Authorise
    approvals: ApprovalRecordReader | None
    clock: Callable[[], float]
    limits: Settings

    async def record(self, meta: Mapping[str, object]) -> ApprovalRecord | None:
        named = meta.get(APPROVAL_META)
        if self.approvals is None or not isinstance(named, str):
            return None
        return await self.approvals.approval(named)

    async def holder(
        self, operation: str, arguments: dict[str, Any], ctx: Context | None
    ) -> str | None:
        meta = _meta(ctx)
        call = Call(operation, SCOPES.get(operation, READ_SCOPE), _bearer(ctx, meta), meta)
        try:
            caller = await self.authorise(call)
        except CallRefused as exc:
            raise NotAuthorised(f"{operation} refused: {exc}") from None
        if caller.holder is not None or not _workflow(caller):
            return caller.holder
        return _on_approval(await self.record(meta), operation, arguments)

    async def payable(self, claim_id: str, who: str, ctx: Context | None) -> None:
        """The far end's own check on money moving (AHC-0057)."""
        claim = await self.store.get_claim(who, claim_id)
        if not claim.get("found"):
            return  # answered as unknown by the store, never as refused

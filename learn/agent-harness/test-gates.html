The gates and CI

CI runs on every push. Static checks first, then the full test suite, then the four gates, then the container images, which are only pushed when everything is green on main.

What blocks. A merge is blocked by any failing check or test. A release is blocked by a gate failing, a reliability score (pass^k) under its threshold, or any successful attack. An uncertain verdict goes to a person and is never counted as a pass. The baseline may only go up.

pass^k means a case must pass all k repeated runs, not most of them: C(c, k) / C(n, k), averaged over scenarios. The gate runs scripted, once, today; live repeats are designed for nightly and weekly jobs, as are pre-commit hooks, live golden runs, judges and red team.

def pass_hat_k(passed: int, runs: int, k: int) -> float:
    """The chance that k attempts of this scenario all succeed.

    `C(c, k) / C(n, k)`, which is 0 when fewer than k of the runs passed and 1
    when all of them did. Asking for more attempts than were run is not a
    number this can estimate, and says so by refusing rather than by returning
    something plausible.
    """
    if k < 1:
        raise ValueError("k is a number of attempts, so at least one")
    if k > runs:
        raise ValueError(f"pass^{k} needs at least {k} runs; {runs} were made")
    if passed < k:
        return 0.0
    return comb(passed, k) / comb(runs, k)

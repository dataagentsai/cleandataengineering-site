The end-to-end journey: 78 steps

The same message journey as the map, written out as every single action, one per row: from the chat window opening, through sorting, the queue, the loop, the reply, to what happens out of sight after the turn and before the next release. 78 steps in 14 parts. This table is read live from the Series, so it always matches.

Goes inA customer opening the chat window
What happens78 small actions, each saying where it runs and whether it is built
Comes outA reply, a record, and a better next release

Status says whether each step is built in the claims assistant today, is an Azure feature we configure, or is still to build. The design pages and real flows show what actually ran.

Journey 2 · Queue and the loop

Queueing the work · drawn on L8 · Concurrency & flow

#StepRuns inWhat happens, in plain EnglishStatus
24Into the queueAPI → Service BusAgent and search turns go into a queue with a priority and a deadline.To build
25Picked upWorkerAny free worker takes the turn and holds a lease, so no other worker runs it.To build
26One at a timeWorker → PostgreSQLOnly one turn per conversation runs at once; a second message waits its turn.To build
27Too late?WorkerA turn past its deadline isn't started; the customer is told when to expect a reply.To build

Before the loop · drawn on Context assembly

#StepRuns inWhat happens, in plain EnglishStatus
28Start the runWorkerThe agent starts a run with limits on steps, time and cost.Built
29Allowed toolsWorker → MCPIt lists only the tools this customer may use.Built
30Build what the model seesWorkerIt puts together the instructions, tools, history and new message, always in the same order.Built
31Mark untrusted textWorkerAnything that came from outside, such as document text, is marked as data, not instructions.Built
32Keep it short enoughWorkerIf the history is too long, older exchanges in the middle are trimmed.Built

Inside the loop: the model · drawn on Model call

#StepRuns inWhat happens, in plain EnglishStatus
33Our input checkWorkerOur rules check what's about to go to the model, such as an injection attempt.Built
34Into the gatewayWorker → APIMThe request goes to our AI gateway, never straight to a model.Built (adapter)
35Gateway: sign inAPIMThe gateway signs in to Foundry with its managed identity; the agent holds no model key.Azure
36Gateway: allowed modelsAPIMIt checks this agent may use the model it asked for.Azure
37Gateway: token limitAPIMIt checks the agent's and customer tier's tokens per minute; over the limit gets a polite 429.Azure
38Gateway: edge screenAPIM → Content SafetyOptionally, it screens the request with Content Safety at the edge.Azure (optional)
39Gateway: pick a backendAPIMIt sends the call to the first healthy backend: provisioned first, then pay-as-you-go, then a second region.Azure
40Azure input checkFoundry guardrailAzure screens the input for harm and jailbreaks.Azure
41The model answersFoundry modelThe model reads the request and writes its response.Azure
42Azure output checkFoundry guardrailAzure screens what the model wrote.Azure
43Gateway: count tokensAPIM → Azure MonitorOn the way back, the gateway records tokens by agent, model and tier.Azure
44Gateway: not usedAPIMSemantic cache and full prompt logging stay off: answers are personal, and our own redacted record is the log.
45Count the costWorkerThe call's cost is added to the run's spend. Past the ceiling, the run stops.Built
46Answer or tool?WorkerThe model either gives an answer or asks for a tool.Built

Inside the loop: a tool · drawn on Tool call

#StepRuns inWhat happens, in plain EnglishStatus
47Is it allowed?WorkerBefore a tool runs, our rules check it's permitted and that the customer asked for it.Built
48Needs a person?Worker → DBOSIf the action needs approval, such as a payout, the run pauses and asks an adjuster.To build

52Azure tool checkFoundry agent guardrailFor Foundry agents, Azure can also screen tool calls and results.Azure (preview)
53Save progressWorker → PostgreSQLProgress is saved, so a crash resumes from here, not from the start.Built

Inside the loop: when to stop · drawn on When it stops

#StepRuns inWhat happens, in plain EnglishStatus

55No progressWorkerIf the model keeps repeating itself, the loop stops.Built
56RepeatWorkerOtherwise the loop goes back to the model with the new information.Built

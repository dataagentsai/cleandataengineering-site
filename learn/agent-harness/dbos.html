DBOS: work that waits

Some work can't finish inside one turn. A payout over ₹25,000 must wait for a claims handler, which might take an hour. The server might restart in that hour. DBOS is a small Python library that lets a function wait for days and pick up exactly where it left off.

Goes inA payout request, or a hand-off
What happensA DBOS workflow saves each step's result in PostgreSQL and waits for a person's decision
Comes outThe payout made exactly once, or the conversation handed back, even across restarts

Why not just wait in the turn? A web request that waits an hour holds a connection, a thread and a server that can't scale to zero; and if the server restarts, the work is lost. A workflow stores its progress in the database instead, so nothing is held while it waits.

Why DBOS? It runs inside our process and keeps its state in the PostgreSQL we already have. Temporal does the same job well but needs its own servers. DBOS adds no new infrastructure.

Only two functions in the whole harness are workflows: approval.wait and escalation.wait.

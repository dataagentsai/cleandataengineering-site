Budgets, layer by layer

"Budget" means six different things in this harness, one for each size of thing that can run away: a single model call, a trip round the loop, a whole turn, a conversation, a minute of traffic, and a month of spending. Each is enforced in a different place, and each does something different when it is hit.

Goes inA call, a trip, a turn, a conversation, a minute, a month
What happensEach layer counts its own thing and has its own limit, checked where that thing is visible
Comes outThe smallest possible reaction: cut, trim, retry, stop the turn, hand to a person, or email

Why so many? Each runaway is only visible at one size. One answer that rambles is caught per call. A loop that asks for 30 tools is caught per trip. Fourteen calls that are really one stuck task are visible only per turn: that is why the step and cost limits live in the loop, not in the model client. A conversation going round in circles shows only across turns. A bill only shows across a month.

Three kinds of reaction. Some budgets trim and carry on (context, tool results, saved history). Some stop the turn with a named reason and an honest reply, usually "let me pass you to a colleague". The outermost ones only tell someone: the Azure budget never switches anything off.

Two more levels are designed but not configured yet: a team's monthly budget in Cost Management with an alert at 80%, and a token limit per agent identity and customer tier at APIM (not available on the Consumption tier, F-39). The ceiling is checked between calls, because you can't un-spend a call: one call can overshoot, bounded by its 4,096 output tokens. At today's prices twelve trips cost about $0.05, so the $0.50 ceiling has never been reached.

Every per-turn limit sits in one frozen object, Budgets, and can be changed per environment without code (for example CLAIMS_MAX_STEPS). Each "stops" reason is written on the trace, so we can count how often each budget fires; see when the loop stops.

class Budgets(BaseModel):
    """Ceilings that can actually stop a call.

    Two positions, deliberately. `max_output_tokens` is a per-call backstop at
    P3; `max_steps` and `max_cost_usd` are per-task and enforced at P4, because
    only the loop can see that fourteen calls are one runaway task rather than
    fourteen tasks. AAC-0093 and AAC-0008 are different obligations for exactly
    this reason.
    """

    model_config = ConfigDict(frozen=True)

    max_steps: int = 12
    max_cost_usd: float = 0.50
    max_output_tokens: int = 4096
    max_tool_result_chars: int = 8000
    """Tool results are bounded before they enter context — AAC-0105."""
    max_turn_seconds: int = 60
    """Wall clock for one turn (AHC-0096), checked before each step."""
    max_tool_calls_per_step: int = 8
    """How many tool calls one step may plan (AHC-0097). A step budget counts
    steps, so without this one step asking for fifty look-ups — or fifty
    writes — spends one of the twelve and does fifty things."""
    max_tool_calls_per_turn: int = 24
    """How many tool calls one turn may plan across all its steps (AHC-0097).
    Reaching either bound stops the turn before the step's calls run, as
    `tool_call_budget_exhausted` — never a silent cut to the first N (AHC-0059)."""
    max_retries_per_unit: int = 4
    """AHC-0024: retries across the whole turn, every call's together (F-087)."""

@contextmanager
def unit_retries(limit: int) -> Iterator[None]:
    """One unit of work's retry allowance, shared by every call inside it.

    AHC-0024 and F-087: "a retry count exists per unit of work, not per call
    site". Each call kept its own few attempts, so a twelve-step turn could
    retry twenty-four times. Inside this scope every retry spends from one
    budget; when it is gone a failure is raised instead of retried. Outside any
    scope only the per-call bound applies.
    """
    token = _UNIT.set([limit])
    try:
        yield
    finally:
        _UNIT.reset(token)
agent_harness/loop/plan.py:82Tool calls per trip and per turn
def over_fan_out(asked: int, so_far: int, budgets: Budgets) -> str | None:
    """`per_step` or `per_turn`: the bound a plan of `asked` calls would pass, after
    `so_far` calls already planned this turn; `None` when it passes neither."""
    if asked > budgets.max_tool_calls_per_step:
        return "per_step"
    if so_far + asked > budgets.max_tool_calls_per_turn:
        return "per_turn"
    return None

Tech stack: what we chose, and what else there was

For each of the 22 concerns: what it does, what we chose, what Azure offers for it, and what open source offers. They are in the order a turn meets them, then the ones around every turn, then the ones between releases.

Goes inA concern, for example "Model invocation"
What happensLay out the Azure options and the open-source options next to our choice, each marked used, planned, considered or dropped
Comes outA choice you can defend, and a known way out if it changes

The rule from the Series: the specs fix the concern and the port; Azure only fills the binding. The order of preference for each port is a managed Azure service, then open source run on Azure, then our own code, and our own code only where no product does the job. See what stays ours.

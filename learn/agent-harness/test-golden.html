Golden sets

A golden case is one input with a known right answer. The set is generated from the spec's own limits, so the edges are always covered: a 30-day rule gets cases at 29, 30 and 31. The set is committed to Git, frozen, and never edited to make a failing case pass.

Built (reference agent): 35 cases in evals/golden/eligibility.jsonl, each with id, action, entity, row, expected_allowed, expected_agent_alone and the boundary it tests. A committed baseline (golden pass rate, context size, cost per task $0.000945) may never get worse: a ratchet. The claims agent relies on scenarios instead and has no golden JSONL yet.

Designed: splits (gate, holdout, canary), statuses (active, quarantined, retired), expectations (route, must_call, must_not_call, must_include, judges), growth from about 100 cases per job to 300+ with a frozen holdout. Rules: never edit a case to pass; quarantine a flaky case with a deadline; nobody tunes prompts against the holdout.

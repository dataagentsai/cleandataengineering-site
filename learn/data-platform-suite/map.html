How to find your way

  1. Know the part. Click its box above, or find its row in one of the two tables below.
  2. Go to the starting function. Each row names the function where that part begins, with its file and line. The link opens that line on GitHub.
  3. See who starts it. The same row lists the callers. Who calls what lists callers for every function and method in the code.
  4. Find any file. Code index lists every module with what it is for and which page explains it.

How a day is orchestrated, in one paragraph

One script, run_platform.py, owns the day loop. For each day it asks the simulated company to act, moves the day's deliveries to landing, runs ingestion, then silver, then gold, and compares each layer with the true answers. The same script is what the deployed Databricks job runs, as a single task. Underneath, three mechanisms keep the order safe: a lease per dataset so two runs never write one table, bookmarks that move only when a dataset run succeeds, and the run log. The detail, with the job definitions, is on Orchestration, end to end.

Every concern, numbered, and who provides it

The platform's cross-cutting concerns are numbered X1 to X22 in the catalog. X23 and X24 were added on the site's platform page and are not in the catalog's list yet. Who provides it says whether we built the code, Databricks provides the capability and we read or configure it, or both. It is read from the code and from the adopt-first table in the observability notes, not from a claim. The rule counts are computed on 2026-11-19 from the catalog's obligations and the tests of this repository: a rule is tested when a test names it, built only when only code names it, and none when nothing does.

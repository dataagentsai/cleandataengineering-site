Source families: how data leaves a system, and how far each route is proven

Every source system has its own story, but they fall into a few families by how data can leave them. A family is an access route, not a product. One product offers several routes, each in a different family, so the useful question is not 'do you support SAP' but 'through which route, and how far has it been proven'.

The two axes

AxisWhat it isExample
Family (the route)How data can leave a system. The platform implements families.A shared table, a file export, an API, a log of changes
ProductA system with a menu of routes and a policy on which to prefer.SAP offers a shared table, an API, a file export, a database route and events

The mover prefers, in order, a route the vendor certifies, then one that shows changes and deletes, then a bulk export, then query-based reads. A choice that departs from that order needs a recorded reason in the dataset's manifest.

The approach for each family, and the fallback

No single command exists for every product. A warehouse export command is one product's way to meet a family's need. So each family states the capabilities it needs, the approach, and a slower route that works almost anywhere when the best one is missing.

What 'supported' means: the proof levels

LevelMeaning
L0Declared. A name in a list, no code.
L1Code exists (a connector, a generator) but has not been run against a fake or a real source.
L2Run against a fake, an emulator or a local copy.
L3Run against a real instance for a full load, an incremental load, a delete and a schema change.
L4Hardened for production, with secrets, retries, a volume test, a runbook and supported versions written down.

Across 32 routes: 22 at level 0, 5 at level 1, 4 at level 2, 1 at level 3, 0 at level 4. A claim of support should name the route and its level.

Not built yet, or known gaps
  • No route is at level 4. One route (files in Azure storage, CSV through the copy service) is at level 3.
  • The routes marked with an asterisk are not checked against the vendor's current documentation.
  • Most routes need the owner's setup, licence or permission, which this page does not describe.
  • The shared-table kind, the warehouse and database movers with an incremental watermark, and the real change-capture proof are not built.
  • The data is read from the specification catalog as of 2026-11-24; the page does not update itself.

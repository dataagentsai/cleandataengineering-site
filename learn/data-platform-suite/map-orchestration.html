Orchestration: how a day runs, from the job to the last check

A platform needs something that decides what runs when. Here that is two things working together. Databricks Jobs start the work and retry it. Our own code decides what each run does and makes sure runs never collide or skip data.

There is one task. The job's parameters are the number of days, the name of the world calendar, and how long bronze is kept before housekeeping. The task passes them to run_days.py, which sets its environment and runs run_platform.py inside the job. When the loop ends it copies the operations page and the report to a volume and publishes the operations tables.

The loop itself

src/dataplatform/ingest/daybyday.py:102The loop: world acts, deliveries move, ingestion runs, the day is judged.
def run_days(
    world: DayWorld,
    days: int,
    store: MetadataStore,
    writer: BronzeWriter,
    tokenizer: Tokenizer,
    sources: Sources,
    move: Callable[[int, str], None],
    domain: str,
    env: str = "dev",
    prefix: str = "ingest",
    on_day: Callable[[Day], None] | None = None,
    silver: CurrentKeys | None = None,
    run_ingest: Callable[[str, str], RunReport] | None = None,
) -> list[Day]:
    """`run_ingest(run_id, window)` runs the day's ingestion somewhere else (its own process or job) and returns its
    report; without it the ingestion runs here."""
    world.prepare()
    out = []
    for n in range(1, days + 1):
        oracle = world.step(n)
        window = str(oracle["date"])
        move(n, window)
        run_id = f"{prefix}-{window}"
        if run_ingest is not None:
            report = run_ingest(run_id, window)
        else:
            report = ingest(store, writer, tokenizer, sources, domain, env, run_id, Plan("normal", window),
                            silver=silver)
        by = report.by_name()
        bronze = {
            ds: (int(writer.fingerprint(ds, {"_run_id": run_id})["row_count"]), int(want))
            for ds, want in sorted(oracle["bronze"].items())
        }
        day = Day(n, window, report, bronze, [judge(n, f, by.get(f["dataset"])) for f in oracle["findings"]], oracle)
        out.append(day)
        if on_day:
            on_day(day)
    world.finish()
  1. world.step. The simulated company acts for the day and returns the true totals (the oracle).
  2. move. The day's change-capture output and file drops are moved to landing.
  3. ingest. One ingestion run takes everything new to bronze: ingest ingest/runner.py:112.
  4. judge. Bronze row counts are compared with the truth, and each planted incident is judged.
  5. on_day. The caller's hook runs silver, gold, housekeeping and upkeep for the same day, then the next day starts.

Not built yet, or known gaps
  • No schedule or file-arrival trigger is defined. The jobs are started by a person or a command.
  • The platform job with three tasks (ingestion, silver, gold) that --hops job expects is not defined in this snapshot, so that way has not been shown here.
  • Retries are Databricks' job setting plus our source guard for pulls. There is no retry of a failed hop by our code.
  • A rule that jobs wait for their data and not for the clock (ORCH-01) is written in code comments but has no test.

Every concern, one page each

A platform is more than its layers. Some jobs cut across all of them: checking quality, keeping history, controlling access, recording what happened. We call these concerns and number them X1 to X24. Each concern gets one page, and every page has the same shape, so you learn the shape once.

The map

How to read a concern page

  1. Why. One plain paragraph on what goes wrong without this concern.
  2. The picture. Where the concern happens along the data's path. Every box opens the page for that part.
  3. The places. A table: each place the concern is checked, what is checked, and what a failure does.
  4. Request and response. For each major function: what goes in, what comes out, and who calls it.
  5. One real run. Inputs and outputs printed by the code on a small example. Nothing here is typed by hand.
  6. Code and tests. The code cut from the real file, the settings that drive it, the tests, and what is not built.

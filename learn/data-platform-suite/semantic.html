The semantic layer: a metric defined once and checked against a known answer

Gold holds the rows. The semantic layer holds the meaning: what exactly is the on-time-in-full percentage, which columns it is computed from, and by which dimensions it may be cut. A metric is one such named calculation. It is defined once, in a metric file, and everything that shows it is generated from that file.

Without this, the same word ends up with two formulas. One dashboard counts cancelled orders and another does not, and nobody can say which number is right. Here a metric cannot be certified until it comes with a known answer: a number, at a stated place and time, that the simulated tyre company knows to be true.

The steps

  1. Read the metric file. Each file names one gold fact as its source, the dimensions it joins, the dimensions a reader may cut by, and the measures. A source that is not a gold fact, or a join the fact does not have, is refused.
  2. Lint. Linting is checking a definition against rules before using it. The rules cover the view's name, the lifecycle state of each measure, a known answer on every certified measure, and one meaning per word. Any problem stops generation.
  3. Split by certification. Certified measures go into the view that carries the file's name. Measures that are still draft or reviewed go into a second view with the suffix _preview. Deprecated measures go nowhere.
  4. Ask the known answers. Each certified measure's known answer is turned into a query and asked of gold. The result must equal the oracle of the same run.
  5. Generate what people use. One dashboard per domain and one question space are derived from the certified views only.
  6. Render for the product. A separate folder turns all of the above into files for Databricks: view definitions, the known-answer query, dashboard files, the question space, catalog tags, grants and masks.

The first five steps live in src/dataplatform/semantic and name no product. Only the last step knows about Databricks. This is the same split as everywhere else in the platform: a kernel that holds the rules, and a realm that renders them for one product.

Read the first measure. Its expression counts lines that were on time and in full, over the rows whose window is complete, and divides by the number of such rows. It is not additive, which means it cannot be summed across months. Its time dimension is the promised month. Its synonyms are the other words people use for it. Its known answer says that for the south region in November 2026 the value is 0.8961, give or take 0.0005.

Reading and linting

src/dataplatform/semantic/metrics.py:151One metric file becomes one record. The join keys are looked up in the gold manifests.
def metric_view(doc: Mapping[str, Any], gold: Mapping[str, Mapping[str, Any]]) -> MetricView:
    """One metric file -> a metric view. `gold` maps gold manifest names (facts and dimensions) to their documents;
    each join's key and schema come from there, so the metric file names a dimension and nothing more."""
    if doc.get("kind") != "metric_view":
        raise MetricError(f"{doc.get('name')}: kind is not metric_view")
    source = str(doc["source"])
    fact = gold.get(source)
    if fact is None:
        raise MetricError(f"{doc['name']}: source '{source}' is not a gold manifest")
    keys = {str(d["name"]): str(d["key"]) for d in fact.get("dimensions") or ()}
    joins = []
    for j in doc.get("joins") or ():
        if j not in keys or j not in gold:
            raise MetricError(f"{doc['name']}: join '{j}' is not a dimension of {source}")
        joins.append(Join(str(j), keys[j], str(gold[j]["domain"])))
    time_dims = {str(m.get("time_dimension")) for m in doc["measures"] if m.get("time_dimension")}
    dims = tuple(_dimension(d, time_dims) for d in doc["dimensions"])
    return MetricView(
        name=str(doc["name"]),
        domain=str(doc["domain"]),
        source=source,
        source_domain=str(fact["domain"]),
        joins=tuple(joins),
        dimensions=dims,
        measures=tuple(_measure(m, dims) for m in doc["measures"]),
        owner=str((doc.get("owners") or {}).get("dataset", "")),
    )

The function takes the file and the gold manifests. It looks the source fact up and refuses a source that gold does not have. For each join it takes the key column from the fact's own manifest, so the metric file only names a dimension and can never state a wrong key. It then builds the dimensions and the measures.

def lint(views: Iterable[MetricView]) -> list[str]:
    """Problems that stop generation. Empty means every view may be published."""
    views = list(views)
    errors: list[str] = []
    seen_measure: dict[str, str] = {}
    seen_word: dict[str, str] = {}
    for v in views:
        if not VIEW_NAME.match(v.name):
            errors.append(f"{v.name}: metric view names are mv_ + lower snake case (ADR-012, NAME-01)")
        if not FACT_NAME.match(v.source):
            errors.append(f"{v.name}: source '{v.source}' is not a fact_ table")
        errors += [f"{v.name}: join '{j.name}' is not a dim_ table" for j in v.joins if not DIM_NAME.match(j.name)]
        if not v.owner:
            errors.append(f"{v.name}: no owner")
        dim_names = {d.name for d in v.dimensions}
        for m in v.measures:
            where = f"{v.name}.{m.name}"
            if m.certification not in LIFECYCLE:
                errors.append(f"{where}: certification '{m.certification}' is not one of {', '.join(LIFECYCLE)}")
            if m.time_dimension not in dim_names:
                errors.append(f"{where}: time dimension '{m.time_dimension}' is not a dimension of the view")
            if m.certification == "certified" and m.known_answer is None:
                errors.append(f"{where}: certified without a known-answer test (ADR-022, SL-SEM-07)")
            if m.name in seen_measure:
                errors.append(f"{where}: also defined in {seen_measure[m.name]} (SERV-04: defined once)")
                continue  # its words would only repeat the same finding
            seen_measure[m.name] = v.name
            if m.certification != "certified":
                continue
            for word in (m.name, *m.synonyms):
                key = word.lower()
                if key in seen_word and seen_word[key] != where:
                    errors.append(f"{where}: '{word}' already means {seen_word[key]} (one word, one metric)")
                seen_word.setdefault(key, where)
    return errors

The rules are in order: the view's name, the source's name, each join's name, an owner, then for each measure a valid lifecycle state, a time dimension the view has, and a known answer if it is certified. The last two rules look across all views. A measure name that appears in two views is an error, because a metric is defined once. Among certified measures, a name or synonym that already means another measure is an error, because one word must mean one metric.

Known answers: one number everywhere

A known answer is a small test that travels with the metric. It says where to look and what number must be there. The same known answer is used three ways: it is looked up in the oracle, which is the simulated company's own record of what is true, it is asked of gold, and it is asked of the view on the engine. All three must agree.

src/dataplatform/semantic/metrics.py:101The text of a known answer's place and time becomes a list of filters on the view's dimensions.
def parse_where(where: str, dimensions: Iterable[Dimension]) -> tuple[Filter, ...]:
    """'region = 'south' AND promised month = 2026-11' -> filters on the view's dimensions (names ignore case)."""
    by_lower = {d.name.lower(): d.name for d in dimensions}
    filters = []
    for part in re.split(r"\s+AND\s+", where.strip(), flags=re.IGNORECASE):
        lhs, sep, rhs = part.partition("=")
        if not sep:
            raise MetricError(f"known answer filter '{part}' is not 'dimension = value'")
        dim = by_lower.get(lhs.strip().lower())
        if dim is None:
            raise MetricError(f"known answer filter names unknown dimension '{lhs.strip()}'")
        raw = rhs.strip()
        quoted = _QUOTED.match(raw)
        if quoted:
            filters.append(Filter(dim, quoted.group(1), "equals"))
        elif _DAY.match(raw):
            filters.append(Filter(dim, raw, "day"))
        elif _MONTH.match(raw):
            filters.append(Filter(dim, raw, "month"))
        else:
            raise MetricError(f"known answer value '{raw}' is neither 'text', YYYY-MM nor YYYY-MM-DD")
    return tuple(filters)
src/dataplatform/semantic/metrics.py:241One known answer as a test case, and the address under which the oracle keeps the same number.
@dataclass(frozen=True)
class KnownAnswerCase:
    view: str
    measure: str
    time_dimension: str
    answer: KnownAnswer

    @property
    def label(self) -> str:
        return f"{self.view} {self.measure} " + " ".join(f.value for f in self.answer.filters)

    @property
    def oracle_key(self) -> str:
        """The world oracle's address for this answer: the time value first, then the other filter values in order
        ('2026-11/south', '2026-11-12/P-CHN', '2026-11')."""
        time = [f.value for f in self.answer.filters if f.dimension == self.time_dimension]
        rest = [f.value for f in self.answer.filters if f.dimension != self.time_dimension]
        return "/".join(time + rest)

src/dataplatform/semantic/answers.py:28The question written the way the metric view defines it, to be asked of gold directly.
def question_sql(view: MetricView, case: KnownAnswerCase) -> str:
    measure = next(m for m in view.measures if m.name == case.measure)
    joins = " ".join(f"LEFT JOIN {j.name} AS {j.name} ON source.{j.key} = {j.name}.{j.key}" for j in view.joins)
    where = " AND ".join(_where(view, f) for f in case.answer.filters)
    # shiftleft: allow SL-SEC-01 -- the text comes from the reviewed metric file (as known_answers.sql), values are quoted
    return f"SELECT CAST({measure.expr} AS DOUBLE) AS got FROM {view.source} AS source {joins} WHERE {where}"

This is what lets a laptop check the metric before any workspace exists. The query is built from the metric file alone: the measure's expression, a left join to each dimension on its key, and one condition per filter. It runs through the gold reader, on Spark or on DuckDB, with the session set to the business time zone so that a day means a business day.

src/dataplatform/semantic/metrics.py:286Each case is asked of whatever can answer it. A missing value fails.
def check_known_answers(
    cases: Iterable[KnownAnswerCase], read: Callable[[KnownAnswerCase], float | None]
) -> list[Verdict]:
    """Ask `read` (a metric view, the oracle, a dashboard's dataset) each case; a missing value fails."""
    out = []
    for c in cases:
        got = read(c)
        ok = got is not None and abs(got - c.answer.value) <= c.answer.tolerance + 1e-9
        out.append(Verdict(c, got, ok))
    return out

A known answer found a wrong definition

The first version of OTIF % divided by every order line of the month. Asked of gold it gave 0.6706 at full scale where the oracle said 0.8961, because lines whose promised date had not come yet were counted as missed. The definition was changed to count only rows whose window is complete, which is the filter you see in the metric file above. This is the kind of mistake the known answer exists to catch.

Dashboards and the question space

Nothing that people look at is drawn by hand. A dashboard is derived per domain: one page per certified view, and for each certified measure a headline number, a trend over its time dimension, and a breakdown by each other dimension. A question space is a place where a person asks in plain words and a model answers from the data. The platform generates its definition too.

src/dataplatform/semantic/experiences.py:105The question space: certified views only, instructions, sample questions, and the measures it must decline.
def conversation_space(
    name: str, title: str, views: Iterable[MetricView], business_timezone: str, all_views: Iterable[MetricView]
) -> ConversationSpace:
    """`views` are the published views; only the certified ones are attached. `all_views` (as read from the manifest,
    before publishing) supply the measures to decline."""
    certified = sorted((v for v in views if v.certified_only), key=lambda v: v.name)
    allowed = {m.name for v in certified for m in v.measures}
    declined = sorted({m.name for v in all_views for m in v.measures if m.name not in allowed})
    words = [f"{m.name}: {', '.join(m.synonyms)}" for v in certified for m in v.measures if m.synonyms]
    instructions = [
        "Answer only from the attached metric views. Every measure in them is certified (ADR-022); never write your "
        "own formula for a metric and never read any other table.",
        "Show the metric view, the measure and the query with every answer.",
        f"Dates and months are in the business time zone {business_timezone}.",
        "Business words and the measure they mean: " + "; ".join(words) + ".",
    ]
    if declined:
        instructions.append(
            "These measures exist but are not certified; if a question needs one, say it is not "
            "certified yet and do not estimate it: " + ", ".join(declined) + "."
        )
    return ConversationSpace(
        name,
        title,
        tuple(v.name for v in certified),
        tuple(instructions),
        tuple(sample_questions(certified)),
        tuple(declined),
    )

Three things make this safe. Only certified views are attached, so the space cannot read a draft measure even if asked. The instructions list each business word beside the measure it means. And the measures that exist but are not certified are listed by name, with the instruction to say so and not to estimate. For the tyre company those are Net sales value and Tyres cured.

realms/databricks/engine/tasks/semantic_layer.py:34After a run on the engine: each view's number beside gold's and the world's.
def check(spark: Any, generated: Path, report: dict[str, Any]) -> list[dict[str, Any]]:
    """One row per certified known answer: the deployed view's number, gold's (Python) and the world's."""
    rows = spark.sql(_statements((generated / "semantic" / "known_answers.sql").read_text())).collect()
    gold = report.get("gold_known_answers") or {}
    world = report.get("known_answers") or {}
    out = []
    for r in rows:
        view, measure = str(r["view_name"]), str(r["measure"])
        got = None if r["got"] is None else float(r["got"])
        g = next((v for k, v in gold.items() if k.startswith(f"{view}|{measure}|")), None)
        base = view.removesuffix("_preview")  # a preview view answers the certified view's question
        w = next((v.get("world") for k, v in world.items() if k.startswith(f"{base} {measure} ")), None)
        ok = _same(got, g) and _same(got, None if w is None else float(w))
        out.append({"view": view, "measure": measure, "address": str(r["address"]), "view_value": got,
                    "gold_value": g, "world_value": w, "spec_value": float(r["expected"]), "ok": ok})
    return out

This last function is the three-way comparison. It runs the generated query against the views that were just created, and for each row takes the number gold gave in Python and the number the simulated world holds. A row is in order only if the view equals both. The value from the metric file is carried along and reported, not judged, because it only holds at full scale.

Governance: what the catalog must say

A data catalog is the place where tables are listed with their owners, descriptions and labels. The platform does not ask anyone to fill it in. It works out what the catalog must say from the contracts and manifests, compares that with what the catalog holds, and produces the smallest list of changes.

def _diff(ref: ObjectRef, want: Entry, have: Entry | None) -> list[Action]:
    actions = []
    if want.comment is not None and (have is None or have.comment != want.comment):
        actions.append(Action("comment", ref, want.kind, comment=want.comment))
    current = have.tag_map() if have else {}
    to_set = tuple((k, v) for k, v in want.tags if current.get(k) != v)
    if to_set:
        actions.append(Action("set_tags", ref, want.kind, tags=to_set))
    wanted = want.tag_map()
    stale = tuple(sorted(k for k in current if k in MANAGED_TAGS and k not in wanted))
    if stale:
        actions.append(Action("unset_tags", ref, want.kind, keys=stale))
    return actions
src/dataplatform/governance/catalog.py:79The plan for the whole catalog, and also the drift report: an empty plan means the catalog is in step.
def plan_sync(desired: Mapping[ObjectRef, Entry], current: Mapping[ObjectRef, Entry]) -> list[Action]:
    """Actions that make the catalog match the metadata, in a stable order (tables before their columns). Objects the
    metadata does not declare lose only our tags (a dropped contract must not leave its owner tag behind)."""
    actions: list[Action] = []
    for ref in sorted(set(desired) | set(current), key=lambda r: (r.layer, r.schema, r.name, r.column or "")):
        if ref.layer not in SYNCED_LAYERS:
            continue
        want, have = desired.get(ref), current.get(ref)
        if want is not None:
            actions += _diff(ref, want, have)
        elif have is not None:
            stale = tuple(sorted(k for k, _ in have.tags if k in MANAGED_TAGS))
            if stale:
                actions.append(Action("unset_tags", ref, have.kind, keys=stale))
    return actions

Each column gets a classification tag. A contract that says nothing means internal. A column classified restricted is personal data that was replaced by a token before it reached bronze, and is tagged as tokenised. A column classified confidential is tagged as masked. A data product is a gold fact with its metric views, and each silver table and dimension is tagged with the products that read it.

src/dataplatform/access/model.py:130From groups and classified columns to grants, masks and row filters.
def plan_access(model: AccessModel, tables: Iterable[TableSpec]) -> AccessPlan:
    tables = list(tables)
    grants: set[Grant] = set()
    for g in model.groups:
        for layer in g.layers:
            if g.every_domain:
                grants.add(Grant(g.name, "read", "catalog", layer))
                continue
            for t in tables:
                if _reads(g, t) and t.layer == layer:
                    grants.add(Grant(g.name, "use", "catalog", layer))
                    grants.add(Grant(g.name, "use", "schema", layer, t.schema))
                    grants.add(Grant(g.name, "read", "table", layer, t.schema, t.name))
    masks = []
    for t in tables:
        allowed = tuple(g.name for g in model.groups if g.protected == "see" and _reads(g, t))
        masks += [
            ColumnMask(t.layer, t.schema, t.name, c.name, c.logical_type, c.classification, c.tokenised, allowed)
            for c in t.columns
            if c.protected
        ]
    known = {(t.layer, t.schema, t.name) for t in tables}
    for f in model.row_filters:
        if (f.layer, f.schema, f.table) not in known:
            raise AccessError(f"row filter on {f.layer}.{f.schema}.{f.table}: no such published table")
    order = ("catalog", "schema", "table")
    return AccessPlan(
        tuple(sorted(grants, key=lambda x: (x.layer, order.index(x.scope), x.schema, x.name, x.group, x.privilege))),
        tuple(sorted(masks, key=lambda m: (m.layer, m.schema, m.table, m.column))),
        model.row_filters,
        model,
    )
  1. Grants. A group that reads every domain gets read on the whole layer. A group limited to some domains gets read on each of its tables, and permission to enter the layer and the schema.
  2. Masks. Every column classified confidential or restricted gets a mask. The groups allowed past the mask are those declared see that can read the table.
  3. Row filters. A filter names a table, a column, the groups that see every row, and the values each limited group may see. A reader not named on the filter sees no rows. A filter on a table that is not published is refused.
src/dataplatform/access/model.py:176The check: what one group sees in each column of one table.
def visible_columns(plan: AccessPlan, group: str, table: TableSpec) -> dict[str, str] | None:
    """What `group` sees in each column (clear, token or masked); None if it cannot read the table at all."""
    if not can_read(plan, group, table):
        return None
    masks = {m.column: m for m in plan.masks if (m.layer, m.schema, m.table) == (table.layer, table.schema, table.name)}
    out = {}
    for c in table.columns:
        m = masks.get(c.name)
        if m is None:
            out[c.name] = CLEAR
        elif group not in m.allowed:
            out[c.name] = MASKED
        else:
            out[c.name] = TOKEN if m.tokenised else CLEAR
    return out

This function is how the plan is tested without any database. For a group and a table it returns, per column, one of three words. clear is the real value. token is the stored token of a restricted column, which is all even an allowed group ever sees, because nothing in this code turns a token back into the value. masked is the mask. If the group cannot read the table at all it returns nothing.

Not built yet, or known gaps
  • No result of the generated views, dashboards or question space running on a real workspace is in the public snapshot. Treat everything in the Databricks folder as generated and locally tested unless the table above says more.
  • The catalog sync, the grants, the masks and the audit query have not been applied to a live catalog as far as the snapshot shows.
  • Grants are planned, not compared with what exists. The generated file grants what the model says and does not revoke a grant someone made by hand.
  • No row filter is declared for the tyre company. The mechanism is built and tested with a made-up filter.
  • The access file lives in the Databricks folder of the platform repository, not with the tyre manifests.
  • The catalog has no glossary object. Glossary terms are the certified measure names, written as a tag and in the view's comment.
  • The contract and the manifest of the inspection results name different owners. The generator reports the difference and takes the contract's owner. Nobody has decided which is right.
  • The business day of a view's time dimension depends on the session's time zone. Locally the reader sets it. On a workspace the warehouse must be set to the business time zone, and nothing in the generated files does that.
  • Sample questions are derived from the known answers and the first synonym. A metric file cannot yet carry its own wording for them.
  • Net sales value and Tyres cured are not certified, so they appear on no dashboard and the question space declines them.
  • The metric files' known answers hold only at full scale after 14 days. At any other scale the test against the file's value fails for the measures that depend on order volume, and only the test against the oracle of the same run is meaningful.

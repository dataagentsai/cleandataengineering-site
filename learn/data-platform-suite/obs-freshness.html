Freshness: how late is too late

Freshness says how old the newest data is, compared with what the dataset promised. A dataset that promises data no older than two hours is late when its last successful load is older than that.

The promise is not written in code. Each dataset's manifest states it, and the freshness functions read it from the metadata store. A dataset with no target is not checked at all.

Two measures, because one is not enough

MeasureThe questionWhat it is based onWhat it catches
Dataset freshnessHow long since this dataset last loaded successfully?The end time of the newest dataset run with status succeededA source that stopped sending, or a job that stopped running
Feed freshnessIs one feed of this dataset behind the others?Each bookmark of the dataset whose value is a time, compared with the newest such bookmarkOne dealer's monthly file missing while every other dealer's arrived

A bookmark is a named position the metadata store keeps for a dataset. Ingestion keeps one bookmark per dealer for the dealer sell-out files, holding the newest data time in that dealer's file. A run that found nothing new still counts as a successful load for dataset freshness: the platform looked, and it is current with its source.

Goes inThe dataset's targets from the metadata store, the dataset runs from the run log, and the dataset's bookmarks.
What happensFor each dataset with a target, the age of the last success is compared with the two targets. Then each time-valued bookmark is compared with its newest sibling.
Comes outOne result per dataset and one per bookmark, each with a state: ok, warn, error or never.

The code

src/dataplatform/obs/freshness.py:73A dataset's targets, read from the merged view the metadata store gives.
def target_from_view(view: dict[str, Any], tiers: dict[str, int] | None = None) -> FreshnessTarget | None:
    """A dataset's targets from the store's merged view; None when the dataset declares no freshness target."""
    settings = view.get("settings") or {}
    if "sla_freshness_hours" not in settings:
        return None
    warn = float(settings["sla_freshness_hours"])
    error = float(settings.get("sla_freshness_error_hours", warn * 2))
    owners = (view.get("manifest") or {}).get("owners") or {}
    name = f"{view['source']}.{view['dataset']}"
    return FreshnessTarget(view["source"], view["dataset"], warn, error, tier_for(error, (tiers or {}).get(name)),
                           str(owners.get("alerts") or owners.get("dataset") or ""),
                           str(owners.get("dataset") or ""))

The function returns nothing when the dataset has no warning target, and that dataset is then left out of every freshness check. The error target falls back to twice the warning target. The rota falls back to the dataset owner.

src/dataplatform/obs/freshness.py:64The tier from the error target, unless the alert configuration forces one.
def tier_for(error_hours: float, override: int | None = None) -> int:
    if override is not None:
        return override
    for limit, tier in TIER_BY_ERROR_HOURS:
        if error_hours <= limit:
            return tier
    return 3

A tier says how urgent a dataset is. An error target of 4 hours or less is tier 1. An error target of 48 hours or less is tier 2. Anything longer is tier 3. The alerts page shows what each tier means for who is told.

src/dataplatform/obs/freshness.py:98The whole rule for a state.
def state_of(age_hours: float | None, warn: float, error: float) -> str:
    if age_hours is None:
        return "never"
    if age_hours > error:
        return "error"
    return "warn" if age_hours > warn else "ok"
src/dataplatform/obs/freshness.py:127Both measures. It returns one result per dataset, then one per time-valued bookmark.
def check(targets: list[FreshnessTarget], datasets: list[DatasetRunRow],
          bookmarks: dict[tuple[str, str], dict[str, str]], now: datetime) -> list[FreshnessResult]:
    """Every target's dataset freshness, then each time-valued bookmark's lag behind its newest sibling."""
    seen = last_success(datasets, now)
    out = []
    for t in targets:
        at = seen.get((t.source, t.dataset))
        age = _hours(now, at) if at else None
        out.append(FreshnessResult(t.source, t.dataset, "", "last_success" if at else "none", age,
                                   t.warn_hours, t.error_hours, state_of(age, t.warn_hours, t.error_hours),
                                   t.tier, now))
        times = {k: v for k, raw in sorted(bookmarks.get((t.source, t.dataset), {}).items())
                 if (v := _as_time(raw)) is not None}
        if len(times) < 2:  # noqa: PLR2004 - a lag needs a sibling to lag behind
            continue
        newest = max(times.values())
        for key, value in times.items():
            lag = _hours(newest, value)
            out.append(FreshnessResult(t.source, t.dataset, key, "bookmark_lag", lag, t.warn_hours,
                                       t.error_hours, state_of(lag, t.warn_hours, t.error_hours), t.tier, now))
    return out

Walk through it. The helper last_success finds, for each dataset, the newest run that succeeded, has an end time, and ended before now. A run still open does not count, and a failed run does not count. The age is the hours from that end time to now. Then the bookmarks: only values that parse as a time with a time zone are kept, so a shard position such as 1234 is ignored. With fewer than two such bookmarks there is nothing to lag behind, and the loop moves on. Otherwise each bookmark's lag is its distance from the newest one, and the same two targets decide its state.

src/dataplatform/obs/freshness.py:154The one moment at which a lateness check is worth running.
def next_due(targets: list[FreshnessTarget], datasets: list[DatasetRunRow], now: datetime) -> datetime | None:
    """When the next dataset would pass its error target if nothing loads before then: the one moment a lateness
    check is worth running (ADR-024 rule 4, no fixed interval). None when nothing can become late (never loaded
    datasets are already reported as `never`; a bookmark lag does not grow with the clock)."""
    seen = last_success(datasets, now)
    due = [at + timedelta(hours=t.error_hours) for t in targets if (at := seen.get((t.source, t.dataset)))]
    later = [d for d in due if d > now]
    return min(later) if later else None

Lateness has no event. Nothing happens when data fails to arrive. So instead of checking on a fixed interval, the monitor asks this function when the next dataset would pass its error target if nothing loads, and checks only then. A dataset that is already late is skipped, because checking it again changes nothing.

The success criteria and the scorecard

Freshness is one promise. The platform also keeps one list of twenty criteria that say what a good run means, each with a single metric and a target. After a run, a scorecard gives each criterion one of three states: met, not met, or not measured. A criterion the run cannot see is never counted as met.

Eight of the twenty are measured by a run from its own evidence: C1 to C5, C8, C9 and C15. The other twelve are reported as not measured, with the note that they are measured outside the run. The two timeliness numbers in the code are these. The hop from bronze to silver must take 30 minutes or less at the 95th percentile. One simulated day through all layers at one tenth of full volume must take 6 minutes or less.

src/dataplatform/obs/success.py:122The hop latency criterion. The hop from source commit to bronze is shown as context and not judged.
def _c8(e: Evidence) -> tuple[str, str, str]:
    seen = {h: s for h, s in e.hops.items() if h in HOP_TARGETS}
    if not seen:
        return "not_measured", "", "no hop stamps in this run"
    over = {h: s for h, s in seen.items() if s > HOP_TARGETS[h]}
    value = ", ".join(f"{h} {s / 60:.1f} min" for h, s in sorted(seen.items()))
    context = "; ".join(f"{h} {e.hops[h] / 60:.0f} min (context, not judged)" for h in CONTEXT_HOPS if h in e.hops)
    why = "worst dataset p95, from the world's clock (simulated schedule)" + (f"; {context}" if context else "")
    return ("not_met" if over else "met"), value, why

The scorecard rows travel with the operations tables as a sixteenth table, ops_success, so the run's score can be published beside its other tables.

Not built yet, or known gaps
  • Criterion C7, the share of days whose gold is complete by 06:00 business time, is in the list but no code measures it.
  • The freshness target is measured from the end of the last successful load, not from the age of the newest row in gold. A freshness target measured end to end is an obligation in the catalog that no test cites.
  • In a local simulated run the platform loads once per simulated day, so datasets that promise hourly freshness show breaches between days. The operations page says so in its subtitle.
  • Criterion C20's target text says 89 of 89 rules. The catalog snapshot beside this code holds 105 obligations, as Proof by layer reports.
  • Hop latency from a simulated run uses the simulated clock, so it describes the schedule and not the speed of a real network.

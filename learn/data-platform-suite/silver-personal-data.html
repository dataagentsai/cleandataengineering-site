Stage 7: personal data, tokens only

Some columns hold personal data, such as a dealer's contact address or an inspector's id. The contract marks them restricted. Ingestion replaces their values with tokens before bronze. A token is a stand-in text that is the same for the same value but cannot be turned back into it. The seventh stage is the guard behind that promise: it checks that every restricted column really holds tokens.

Without the guard, one misconfigured source would put plain personal data into silver, and from there into every table and report built on it, and nobody would notice.

Goes inRows after standardising, and the token format the deployment uses.
What happensEach restricted column's value is matched against the token pattern.
Comes outRows whose restricted values are tokens or missing go on. The others go to quarantine.

src/dataplatform/adapters/keyed_tokens.py:24How that tokenizer makes a token: the first 24 hex digits of a keyed hash, after a fixed prefix.
    def token(self, column_class: str, value: str) -> str:
        digest = hmac.new(self._key, f"{column_class}\x1f{value}".encode(), hashlib.sha256).hexdigest()
        return f"tok_{digest[:24]}"

Read the pattern piece by piece. ^ is the start of the value. tok_ is the literal prefix. [0-9a-f]{24} is exactly twenty-four characters, each a digit or a letter from a to f. $ is the end. So a value is a token only if it is the prefix followed by exactly twenty-four hex digits and nothing else.

The code

src/dataplatform/stages/clean.py:187The whole stage.
def personal_data(df: DataFrame, ctx: StageCtx) -> Out:
    """A restricted column must hold tokens, never the plain value (DPC-0070): a row with a plain value is quarantined.
    The token format comes from the binding's tokenizer."""
    restricted = [c for c in ctx.plan.kept if c.restricted]
    if not restricted:
        return Out(df)
    if not ctx.plan.token_pattern:
        raise StageError(f"{ctx.plan.table}: restricted column(s) and no token format bound to check them")
    checks = [
        (F.col(c.name).isNotNull() & ~F.col(c.name).rlike(ctx.plan.token_pattern), f"{c.name} is not tokenised")
        for c in restricted
    ]
    good, bad = quarantine_rows(df, reasons(checks), "personal_data")
    return Out(good, bad)
  1. Find the restricted columns. The kept columns whose classification is restricted. If there are none, the frame is returned as it came.
  2. Refuse to guess. If there are restricted columns but no token pattern, the stage raises a stage error. Passing the rows unchecked would be the silent failure the stage exists to prevent.
  3. Build one check per column. The check is true when the value is present and does not match the pattern. rlike is a match against a regular expression. The sign ~ means not.
  4. Split. quarantine_rows sets aside every row with at least one failed check. A row with two plain values gets both reasons.

The privacy scan beside the stage

The same folder holds a second, smaller function. It is not one of the thirteen stages. It is a scan that can be run over bronze and silver at any time and counts, for each restricted column, the values that are present and do not look like a token.

src/dataplatform/stages/privacy.py:13The scan: one pass over the frame, one count per column.
def clear_counts(df: DataFrame, columns: list[str], pattern: str) -> dict[str, int]:
    """Values present in each column that do not match the token pattern."""
    cols = [c for c in columns if c in df.columns]
    if not cols:
        return {}
    row = df.agg(*[F.sum(F.when(F.col(c).isNotNull() & ~F.col(c).cast("string").rlike(pattern), 1).otherwise(0))
                   .alias(c) for c in cols]).first()
    return {c: int((row[c] if row else 0) or 0) for c in cols}

For each column it adds up 1 for a value that is present and does not match, and 0 otherwise. All columns are counted in a single aggregation, so the frame is read once. A column the frame does not have is left out of the answer. The stage stops bad rows on the way in. The scan proves afterwards that none is there.

Not built yet, or known gaps
  • The quarantine record keeps every column of the row, so the plain value that caused the quarantine is stored in the quarantine table as it arrived. The quarantine table therefore needs the same protection as the source. I found no code that masks it.
  • The stage checks the shape of a value, not where it came from. A text that happens to look like a token passes.
  • Only the classification restricted is acted on.
  • The stage does not create tokens. If ingestion did not tokenise, every row of the batch is quarantined.
  • Switching the stage off with processor_groups.pii removes the check entirely. Nothing else in silver looks at restricted columns during a run.

The 24 tables at a glance: purpose and an example row

The store has 24 tables in two schemas. The config schema says what to load and how. The runtime schema says what happened. This page gives each table's purpose and one example row. The example values are made up in the shape of the tyre company's data. The table and column names are the real ones.

Why so many? Key and value rows are right for flat settings. They are wrong for three kinds of fact: lists (columns, keys, rules), facts that must change together (a run closing and its watermark moving), and records that must never be edited (audits, voids, corrections). Each of those has its own typed table.

Config: what to load and how (9 tables)

TablePurposeExample row
config.setting_defThe registry of every allowed setting: scope, type, default and allowed values. A setting that is not here is refused (DPM01), so a typo cannot silently do nothing.scope dataset, key silver_engine, default job, allowed job, declarative
config.domainOne business area loaded as a unit. Holds its business timezone (what a day means), its environments, the whole manifest as loaded and the manifest's fingerprint.tyre, Asia/Kolkata, environments dev, prod
config.domain_settingSettings for the whole domain (the platform-level configuration). Only values that differ from the registry default are stored.domain tyre, key table_format, value iceberg-uc
config.sourceOne system the data comes from, inside a domain.source id 2, domain tyre, name erp, environment prod
config.datasetOne table or feed of a source: identity, kind, how it is ingested, its history type, the contract it follows, and the manifest it came from.sales_order_line, enabled, history scd2, contract sales_order_line 1.2.0
config.dataset_settingSettings for one dataset. They override the domain's value.dataset 14, key silver_engine, value declarative
config.dataset_columnThe columns of a dataset, in order, from its contract: type, required flag, primary-key position and personal-data class.dataset 14, position 3, dealer_id, string, required
config.business_keyWhich columns identify a row: the primary key for history and merge, and the dedup key for removing duplicates.dataset 14, kind primary, position 1, order_id
config.dq_ruleOne data-quality rule of a dataset, written from the contract: the check, its severity and what happens when it fails (quarantine the rows, stop the load or warn).rule qty_positive on quantity, check min 1, severity major, action quarantine

Runtime: what happened (15 tables)

TablePurposeExample row
runtime.config_snapshotThe exact merged configuration, stored once per fingerprint. Every dataset run points at one, so a past run is explained by the configuration it really used.fingerprint 4be1…, the merged settings as JSON, first seen 20 Nov 06:00
runtime.runOne platform run: a trigger for a domain in an environment. Its status follows its dataset runs.domain tyre, env dev, trigger schedule, type normal, status succeeded
runtime.dataset_runOne dataset's part of a run: status, the configuration used, the watermark before and after, and row counts.dataset 14, succeeded, watermark 2026-11-19 to 2026-11-20, counts rows_in 12840, quarantined 3
runtime.step_logOne step inside a dataset run. The step names are the contract with observability.step quality.sales_order_line, warned, 3 rows quarantined
runtime.file_logEvery delivered file or batch: name, window, checksum, rows declared and rows read, outcome. The authority for what is already handled, and append-only.sol_20261120.parquet, declared 12843, read 12843, status loaded, load type incremental
runtime.error_logA failure with its class, its step and a redacted message (secrets removed, capped at 4000 characters).step land, class ChecksumMismatch, file changed since first delivery
runtime.watermarkThe high-water mark of a dataset. It moves in the same transaction that closes a successful run, never before.dataset 14, value 2026-11-20
runtime.bookmarkA named cursor, for when one watermark is not enough: a shard or a change-feed position.dataset 21, key dms_feed, value 00004812
runtime.watermark_auditWho moved a watermark by hand, from what to what and why. Append-only.dataset 14, 2026-11-20 to 2026-11-15, reason: supplier resent a week
runtime.backfill_planA planned reprocessing: which windows, from which date and why.plan BF-017, window 2026-10, active from 22 Nov, reason: wrong unit price
runtime.correctionOne corrected value under a backfill plan. Silver is never edited: the correction is a row and gold is rebuilt from it.plan BF-017, order A-1002 line 1, field unit_price, value 41.50, was 14.50
runtime.dq_resultWhat each quality rule found in each run: counts only, never the failing rows.rule qty_positive, checked 12843, failed 3, action quarantine
runtime.dq_profileA statistical profile of what a run loaded (counts, nulls, ranges). The newest one is what drift is compared against.rows 12840, quantity min 1, max 96, nulls 0
runtime.batch_voidA loaded batch declared not to count, with a reason and an approver. The file log is not touched.batch erp/sales_order_line/2026-11-18, reason: duplicate export, approved by the data owner
runtime.table_leaseA short lock so only one run writes a table at a time. A lease past its expiry (a crashed run) is taken over.table silver.erp__sales_order_line, run 7e3a…, expires 06:30

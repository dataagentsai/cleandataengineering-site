The simulated tyre company

The simulated company is a program that pretends to be a tyre maker. It runs for simulated days. Each day it takes orders, cures tyres, inspects them, receives dealer files and emits sensor readings, and writes all of it into mock source systems.

It exists because real data cannot be used to prove a platform. With real data nobody knows the right answer. With generated data the generator knows exactly what it produced, so every number the platform shows can be checked.

The world file

The company is described in one file, data-platform-catalog/slices/02-tyre/world.yaml. The file says what the sources are, how much they produce, when the clock starts, and which incidents happen on which day. It does not declare columns or keys. Those come from the dataset manifests and contracts that it cites, so the simulated company and the platform read the same specification.

The six source systems

The table lists the six systems in the world file. The second column is the kind of source, the third the datasets it holds, and the fourth how it delivers.

mes_dbDatabase with a change feedProduction batches, pressesProduction every 15 minutes. Presses as a full copy daily at 01:00.

press_streamEvent streamPress readingsOne reading per press every 10 seconds.

A change feed is a list of every insert, update and delete in the order the database committed them. A full copy is the whole table sent again. Between them the six systems cover every way the platform can read a source.

How one simulated day runs

  1. The domain model produces the day. It works out everything the sources did that day and returns it as one object.
  2. The engine writes it through ports. Each output goes to the port that matches its system's kind. A write to a system the world file does not declare is refused.
  3. The oracle is saved. The model computes what a correct platform should show at the end of the day, and the engine writes it as one file for that day.
  4. The platform runs. The caller runs ingestion, then silver, then gold, and compares each with the oracle file.
src/dataplatform/world/engine.py:90One world day: write the sources, then save the oracle.
    def step(self, day: int) -> dict[str, Any]:
        """One world day: the sources' output written through the ports, then the oracle's totals saved. Days run in
        order from 1 after prepare(), so a caller can run the platform between two days."""
        (self.out / "oracle").mkdir(parents=True, exist_ok=True)
        emission = self.model.day(day)
        written = self.write(emission)
        oracle = self.model.oracle(day)
        oracle["written"] = written
        (self.out / "oracle" / f"day-{day:02d}.json").write_text(json.dumps(oracle, indent=1, sort_keys=True))
        for name, note in emission.notes.items():
            (self.out / "world").mkdir(parents=True, exist_ok=True)
            (self.out / "world" / name).write_text(json.dumps(note, indent=1, sort_keys=True))
        return oracle

The engine knows nothing about tyres. It only checks that the model writes to declared systems through the right port, and that the model can plant every kind of incident on the calendar. If the calendar names a kind the model has no handler for, the engine refuses to start and names it.

src/dataplatform/world/engine.py:72The refusal at start-up.
class World:
    def __init__(self, dwd: Dwd, model: DomainModel, sinks: Sinks, out_dir: str | Path):
        self.dwd, self.model, self.sinks, self.out = dwd, model, sinks, Path(out_dir)
        unhandled = sorted({e["kind"] for e in dwd.world.get("calendar", [])} - set(model.handles))
        if unhandled:
            raise WorldError(f"the domain model cannot plant incident kind(s) {unhandled}; add them or fix the DWD")

src/dataplatform/world/dwd.py:67Applying a named calendar. Every incident must be moved, and the order of days must hold.
def apply_calendar(world: dict[str, Any], name: str) -> dict[str, Any]:
    """A named calendar from the world's `calendars:` block moves incidents to other days (for a short run that still
    meets every incident). Every incident must be moved, a moved key must be `day` or one of its day params, and the
    order of days must hold; anything else is an error, never a silent default."""
    variants = world.get("calendars") or {}
    if name not in variants:
        raise DwdError(f"no calendar {name!r} in the world (have: {sorted(variants)})")
    moves = variants[name].get("moves") or {}
    ids = [e["id"] for e in world.get("calendar", [])]
    if sorted(moves) != sorted(ids):
        raise DwdError(f"calendar {name}: moves must name every incident; missing {sorted(set(ids) - set(moves))}, "
                       f"unknown {sorted(set(moves) - set(ids))}")
    out = []
    for entry in world["calendar"]:
        move, params = dict(moves[entry["id"]]), dict(entry.get("params") or {})
        unknown = [k for k in move if k != "day" and k not in params]
        if unknown:
            raise DwdError(f"calendar {name}, {entry['id']}: {unknown} are not this incident's params")
        day = int(move.pop("day", entry["day"]))
        params.update(move)
        wrong = [k for k in BEFORE if k in params and not int(params[k]) < day]
        wrong += [k for k in AFTER if k in params and not int(params[k]) > day]
        wrong += [k for k in NOT_BEFORE if k in params and not int(params[k]) >= day]
        if wrong or day < 1:
            raise DwdError(f"calendar {name}, {entry['id']}: day {day} breaks the order of {wrong or ['day']}")
        out.append({**entry, "day": day, "params": params})
    changed = _set_paths(world, variants[name].get("world") or {}, name)
    return {**changed, "calendar": out, "calendar_name": name}

The three rules at the bottom are the order of days. A day the incident reaches back to must be before the incident. A later effect must be after it. A last day must not be before it. A calendar that breaks one of these is refused, never quietly adjusted.

How it is run

ScriptWhat it does
scripts/run_world.pyRuns the company alone for a number of days and writes the sources and the oracle files. It is the binding for the local stack: the only place that picks adapters for the sources.
scripts/run_platform.pyRuns the company and the platform together, day by day. After each world day it runs ingestion, silver and gold, compares each with the oracle, judges the day's incidents, and at the end writes a report and the operations page.
src/dataplatform/ingest/daybyday.py:102The day loop: world step, movers, ingestion, then bronze against the oracle.
def run_days(
    world: DayWorld,
    days: int,
    store: MetadataStore,
    writer: BronzeWriter,
    tokenizer: Tokenizer,
    sources: Sources,
    move: Callable[[int, str], None],
    domain: str,
    env: str = "dev",
    prefix: str = "ingest",
    on_day: Callable[[Day], None] | None = None,
    silver: CurrentKeys | None = None,
    run_ingest: Callable[[str, str], RunReport] | None = None,
) -> list[Day]:
    """`run_ingest(run_id, window)` runs the day's ingestion somewhere else (its own process or job) and returns its
    report; without it the ingestion runs here."""
    world.prepare()
    out = []
    for n in range(1, days + 1):
        oracle = world.step(n)
        window = str(oracle["date"])
        move(n, window)
        run_id = f"{prefix}-{window}"
        if run_ingest is not None:
            report = run_ingest(run_id, window)
        else:
            report = ingest(store, writer, tokenizer, sources, domain, env, run_id, Plan("normal", window),
                            silver=silver)
        by = report.by_name()
        bronze = {
            ds: (int(writer.fingerprint(ds, {"_run_id": run_id})["row_count"]), int(want))
            for ds, want in sorted(oracle["bronze"].items())
        }
        day = Day(n, window, report, bronze, [judge(n, f, by.get(f["dataset"])) for f in oracle["findings"]], oracle)
        out.append(day)
        if on_day:
            on_day(day)
    world.finish()
    return out

How the simulated company itself is tested

The golden data must be right before anything is judged against it. test_world_tyre.py (12) runs fourteen days at scale 0.05 once and checks many things on that one run. Each incident is found in the sources on its day. The oracle's silver numbers equal what the mock sources actually hold. Bronze never exceeds what the sources sent. The same seed gives the same world. The clean days are days 1, 2 and 14. test_world_calendar.py (5) covers the named calendars.

Not built yet, or known gaps
  • Volume is not realistic. The world file says so itself: thousands of rows a day, not millions.
  • Prices and margins are plausible but not modelled, and the shop floor beyond the presses is not simulated.
  • The database and the dealer interface have only local adapters. The file drop and the stream also have cloud adapters.
  • There is one domain model, the tyre company. A second company would need its own model.
  • A new kind of incident needs a handler in the model's code. The world file alone cannot add one.

Data quality: what happens to a bad row

Data from a source is never perfect. A quantity is negative, a plant code does not exist, a required value is empty. Data quality is the job of noticing this and deciding what happens next, without stopping the good data and without letting the bad data into a report.

Two simple designs both fail. If every problem stopped the load, one bad record would hold back a day of good ones. If every problem were only logged, bad rows would end up in dashboards. This platform grades each rule by severity, and the severity decides the outcome.

One real run

Four sales order lines go through the quality stage with five rules in the plan: the order id and the dealer code must be filled (critical), the quantity is never negative (critical), the plant code is one of two (major), and the press cycle state is one of four known states (minor, flag only). The block below was printed by the code on a local Spark session, not typed. The code that produced it is the same stage function the daily run calls.

COMES OUT 2: quarantine records (stage, reason, original row)

  flagged  = 0
  critical = 2

Read it like this. SO-1001 is clean and has no flags. SO-1002 has a plant that does not exist: major, so it is quarantined. SO-1003 has a negative quantity and SO-1004 has no dealer code: both are critical, so the critical count is 2. The silver runner then holds the whole batch, which means even SO-1001 is not written until the batch is voided or resent. SO-1004's cycle state, resting, is not a known state, but the row was quarantined for the missing dealer, so no flag was added and flagged is 0. Had it been the only problem, the row would have stayed in silver with cycle_state-invalidValues-1 in _dq_flags.

The code

src/dataplatform/stages/clean.py:216The whole stage: build a failure condition per rule, sort the rules by action, quarantine, flag, count.
def quality(df: DataFrame, ctx: StageCtx) -> Out:
    """Row rules; severity sets the action (ADR-009): quarantine the row, or flag it in _dq_flags and keep it."""
    unknown = sorted({r.action for r in ctx.plan.rules if r.action not in ("quarantine", "flag", "none")})
    if unknown:  # a rule whose action the stage does not know must never be silently skipped
        raise StageError(f"{ctx.plan.table}: rule action(s) {', '.join(unknown)} are not quarantine, flag or none")
    fails = [(r, ~F.coalesce(F.expr(r.predicate), F.lit(False))) for r in ctx.plan.rules if r.action != "none"]
    held = [(cond, r.name) for r, cond in fails if r.action == "quarantine"]
    flagged = [(cond, r.name) for r, cond in fails if r.action == "flag"]
    critical = [cond for r, cond in fails if r.action == "quarantine" and r.severity == "critical"]
    good, bad = quarantine_rows(df, reasons(held), "quality")
    good = add_flags(good, flagged)
    tally = {"flagged": good.where(F.size("_dq_flags") > 0)} if flagged else {}
    if critical:  # ADR-009: any row that breaks a critical rule blocks the batch (the runner holds it)
        tally["critical"] = df.where(reduce(lambda a, b: a | b, critical))
    return Out(good, bad, tally)
src/dataplatform/silver/contract_rules.py:34One contract rule in; one stage rule or one reason out.
def translate(rule: DqRule) -> Rule | str:
    """The quality-stage rule, or the reason it is not one."""
    p = rule.params
    action = ROW_ACTION.get(rule.action)
    if action is None:
        return f"{rule.rule_id}: action '{rule.action}' has no row meaning, not translated"
    if rule.check in HANDLED_ELSEWHERE and not rule.column:
        return f"{rule.rule_id}: a table rule, kept by {HANDLED_ELSEWHERE[rule.check]}"
    if rule.check == "invalidValues" and rule.column and _IDENT.match(rule.column):
        valid = (p.get("arguments") or {}).get("validValues")
        if isinstance(valid, list) and valid and int(p.get("mustBe", 0)) == 0:
            allowed = ", ".join(_quote(v) for v in valid)
            return Rule(rule.rule_id, f"{rule.column} IS NULL OR {rule.column} IN ({allowed})", rule.severity,
                        action)
    if rule.check == "sql":
        m = _COUNT_WHERE.match(str(p.get("query") or ""))
        if m and int(p.get("mustBe", -1)) == 0:
            cond = m.group("cond")
            if _UNSAFE.search(cond):
                return f"{rule.rule_id}: the condition is not a plain row condition, not translated"
            return Rule(rule.rule_id, f"coalesce(NOT ({cond}), true)", rule.severity, action)
    return f"{rule.rule_id}: check '{rule.check}' is not a row rule this stage can run, not translated"

Not built yet, or known gaps
  • QUAR-01: a released row should go through the same checks again. Nothing in the code does this yet.
  • LATE-04: time zones and business dates have no rule or test yet.
  • SCD-04: facts joined to the right version of history is not tested yet.
  • The data quality results table is never written in a normal run. Rule verdicts are in the run log, not in a table of their own.
  • Declarative-engine expectations are described on Declarative engine, and are separate from the stage above.

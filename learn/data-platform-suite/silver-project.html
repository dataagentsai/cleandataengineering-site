Stage 2: project, choosing and naming the columns

The second stage decides which columns go on and what they are called. After it, every contract column has its contract name, whatever the source called it, and every later stage can work with contract names only.

By default no column is thrown away. A column the source added that the contract does not know still reaches silver. Without that rule a new source column would be lost until someone changed the contract and reloaded history.

Goes inBronze rows with the source's column names and the columns the lander stamped.
What happensOne select builds the new column list in a fixed order.
Comes outThe same rows. Contract columns first, then other source columns, then the underscore columns, then _dq_flags.

A worked example

The code

src/dataplatform/stages/clean.py:54The whole stage. It ends in one select.
def project(df: DataFrame, ctx: StageCtx) -> Out:
    """All columns by default (ADR-008): contract columns under their contract names (renamed or extracted from the
    held columns), every other source column too unless the projection is 'declared'; excluded columns go."""
    plan = ctx.plan
    for c in plan.columns:
        if not _NAME.match(c.name) or not _NAME.match(_source_name(c)):
            raise StageError(f"{plan.table}: {c.name!r} is not a safe column name")
    sources = {_source_name(c) for c in plan.columns} | {c.name for c in plan.columns}
    picked = [
        (F.get_json_object(F.col("_extra"), c.path) if c.path else F.col(_source_name(c))).alias(c.name)
        for c in plan.kept
    ]
    others = [F.col(x) for x in df.columns if x not in sources and not x.startswith("_")]
    meta = [F.col(x) for x in df.columns if x.startswith("_") and x not in sources and x != "_dq_flags"]
    flags = F.col("_dq_flags") if "_dq_flags" in df.columns else no_flags()
    return Out(df.select(*picked, *(others if plan.projection == "all" else []), *meta, flags.alias("_dq_flags")))
src/dataplatform/stages/clean.py:34The pattern a column name must match.
_NAME = re.compile(r"^[A-Za-z_][A-Za-z0-9_]{0,127}$")
  1. Refuse unsafe names. Every contract name and every source name must start with a letter or an underscore and continue with letters, digits or underscores, at most 128 characters in all. Later stages put column names into SQL expressions, so a name with a space or a quote is refused here, with a stage error.
  2. Know which names are spoken for. sources is the set of every contract column's source name and contract name, including the excluded columns. It is used below to decide what counts as another source column.
  3. Pick the contract columns. For each kept column the stage takes the bronze column under its source name, or, when the column has a path, the value at that path inside _extra. Either way it is given the contract name with alias. This is where the rename happens.
  4. Collect the other source columns. others is every bronze column that is not spoken for and does not start with an underscore. An excluded column is spoken for, so it is neither picked nor counted among the others. That is how it disappears.
  5. Carry the underscore columns. meta is every column that starts with an underscore, such as _batch_key, _source_file and _extra. They always go on.
  6. Start the flags. If the frame already has _dq_flags it is kept. Otherwise an empty list of text is created. Later stages append names to it.
  7. Select. The final column list is the picked columns, then the others when the projection is all, then the underscore columns, then _dq_flags.

A value extracted from _extra comes out as text, because get_json_object returns text. Stage 4 then casts it to the contract's type like any other column.

src/dataplatform/stages/common.py:90Why the empty list is written as SQL text.
def no_flags() -> Column:
    """An empty list of flag names. Written as SQL text because an empty F.array() does not compile on every engine
    the stages run on (docs/DUCKDB-SPIKE.md); Spark reads it the same way."""
    return F.expr("CAST(array() AS array<string>)")

Not built yet, or known gaps
  • Keeping only the contract's columns exists in the code but no manifest key selects it. The design note docs/W1C-SILVER.md lists this as a gap in the manifest specification.
  • The manifest's columns list has no typed schema of its own. The plan refuses a key it does not know, which is the only check today.
  • A held column in _extra does not become a real silver column by itself. It needs a contract column with a path.

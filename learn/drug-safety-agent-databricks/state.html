State and the approval step: not built yet

Today the agent produces a draft and stops. The draft is a sentence on a screen. It is not saved anywhere, no person is asked to approve it, and nothing records who decided what. That is the biggest gap between this demo and a real tool, and the tour says so plainly.

not built State · not built Approval queue · not built Escalation desk

What the specification already says. A draft is an assessment that moves through a small state machine. It starts as drafted, and a reviewer moves it to approved, rejected or edited. Those three are final. Only a person can do it; the agent has no tool for it.

Why it matters. The rule "a person decides every draft" is currently true only because nothing else can happen. Once drafts are stored, the rule has to be enforced, and tested.

state_machines:
  assessment_status:
    states: [drafted, approved, rejected, edited]
    terminal: [approved, rejected, edited]
    transitions:
      - {from: drafted, to: approved, by: approve_assessment}
      - {from: drafted, to: rejected, by: reject_assessment}
      - {from: drafted, to: edited, by: edit_assessment}
    concurrent_writers: [reviewer]

  approve_assessment:
    entity: assessment
    side_effect: irreversible
    offered: false
    input: [assessment_id]
    preconditions:
      - {field: status, equals: [drafted]}
    effect: {status: approved}
    identity: assessment_id
    compensation: {kind: none, how: "a decided assessment is final; a new draft starts a new assessment"}
    authority: human_approval

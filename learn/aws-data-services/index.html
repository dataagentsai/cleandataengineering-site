AWS services for data platforms and streaming

Every AWS service our data platform and streaming pages use, on one picture and in one table. Each has its own page, about a 10-minute read: what it is in plain words, where it fits, what goes wrong in production, what to compare it with, cost, and a verdict.

How to read this: data moves left to right, from the systems that create it to the people and apps that use it. The band at the bottom is the services every part needs. Verdicts are for a platform built on AWS with Databricks doing the processing: 26 Pursue, 16 Pursue with care, 18 Keep if you have it, 6 Drop.

The big picture

Every service, in its place

Names under each lane are the services that do that job. Open any of them in the table below.

FAQ

Questions people ask

Which AWS services do I need for a data platform with Databricks?

S3 for storage, IAM, KMS and VPC endpoints for access and privacy, a mover for each source type (DMS for databases, AppFlow for SaaS, Transfer Family for SFTP, Kinesis or MSK for streams) and CloudWatch, CloudTrail and cost reports to run it. Databricks does the processing, catalog and orchestration.

Kinesis or MSK?

Kinesis Data Streams when you want a managed stream with no cluster and AWS-native producers; MSK when you already speak Kafka, need Kafka Connect or Debezium, or want the same tool on every cloud. Each has its own page here.

Is AWS Glue still needed if I use Databricks?

Usually not for ETL; Databricks jobs and pipelines do that. The Glue Data Catalog still matters if Athena, Redshift or EMR must read the same tables, and Glue Schema Registry if streams use Avro.

What is the Azure equivalent of each AWS data service?

Every row in the table above lists the Azure, Google Cloud and Databricks equivalent, and each service page compares them in more depth.

Amazon Macie

Scans S3 buckets for personal and sensitive data and flags buckets that are public, unencrypted or shared outside your account.

RoleSecurity, identity and network
StatusGenerally available
Verdict on this sitePursue with care
AzureMicrosoft Purview data classification and Defender for Storage sensitive data discovery
Google CloudSensitive Data Protection (formerly Cloud DLP) discovery
DatabricksUnity Catalog data classification on tables (check current status); Macie looks at raw files, Unity Catalog at tables
Open sourceMicrosoft Presidio, or custom regular-expression scans in Spark
Verdict: Pursue with care. A cheap safety net over the landing buckets: it finds personal data that slipped past the tokenising lander. Point it at landing only, not at every Delta table, or the per-GB bill grows with the lake.

In plain words

What it is

Amazon Macie is an AWS service that looks inside your Amazon S3 buckets and tells you where personal or sensitive data is sitting. Personal data means anything that identifies a person: a name, an email address, a phone number, a national ID number such as an Indian PAN or Aadhaar number, a bank account or a credit card number. Macie reads the files, matches what it sees against a library of built-in detectors called managed data identifiers, and writes a finding for every file where it finds a match.

Macie also does a second, simpler job without reading any file. It keeps an inventory of every bucket in the account and checks its settings: is the bucket public, is default encryption on, is it shared with another AWS account, is replication going somewhere unexpected. When a setting is risky it writes a policy finding.

A concrete example: a retail company receives a nightly CSV of loyalty-card orders from a partner over SFTP. The contract says the file holds only a hashed customer key. One night the partner changes its export and the file now carries full names, PAN numbers and delivery addresses. The landing bucket accepts it as it accepts every file. Macie, scanning the landing bucket, finds names and PAN numbers in a column labelled pan and raises a finding. That finding reaches the privacy team through EventBridge before the data has spread into silver and gold tables.

Macie works only on S3. It does not scan databases, Kafka topics or Delta tables as tables; it scans the files underneath. It reads common formats such as CSV, JSON, Parquet, Avro, Excel, PDF, Word documents and compressed archives.

Big picture

Where it fits

The lit lane is where Macie works. Boxes on the left feed it; boxes on the right use what it produces.

On the reference platform, Macie sits beside the landing zone, the first S3 hop where movers such as DMS, AppFlow and Transfer Family drop files exactly as received. The design already keeps personal data out of the lake: the lander swaps names, phone numbers and IDs for tokens as data enters bronze, and the real values live only in a separate token vault. Macie is the check that this promise holds. It scans the landing buckets weekly for personal data in places where the contract says there should be none.

Macie is a detective control, not a preventive one. It does not stop a file from landing. Its findings go to EventBridge and Security Hub, and from there to the privacy team's queue. The usual fix is upstream: the source owner corrects the export, the dataset gets a personal-data tag in its YAML so the lander tokenises the new columns, and the bad landing file is deleted.

Unity Catalog handles the table side. Column tags, masks and data classification on tables cover silver and gold, where data is already typed and governed. Comprehend finds names in free text, such as warranty notes, where a table classifier sees only a long string. Macie covers the gap neither of them reaches: raw files in S3 before any table exists.

How it works

The ideas you need

IdeaWhat it means
Managed data identifierA built-in detector that AWS maintains for one kind of sensitive data, such as credit card numbers, email addresses or a country's tax ID. Many are country-specific.
Custom data identifierA detector you write yourself as a regular expression plus optional keywords near the match, for example an internal employee number or a loyalty-card format.
Allow listText or patterns Macie should ignore, such as the company's own head-office phone number or a test email domain, so they stop raising findings.
Automated sensitive data discoveryA background mode where Macie samples objects across your buckets every day and builds a sensitivity score per bucket, without you defining jobs.
Sensitive data discovery jobA scan you define: which buckets, which identifiers, run once or on a schedule (daily, weekly, monthly). Gives full coverage of the chosen objects.
Sensitive data findingA report that one S3 object holds a given type of sensitive data, with counts and, for many formats, the location (row, column, page) of each match.
Policy findingA report that a bucket's settings got riskier, such as public access allowed, encryption turned off or the bucket shared with an outside account.
Discovery results repositoryAn S3 bucket you must configure where Macie writes a detailed record for every object it analysed, including objects with no findings. It is your evidence of coverage.

Choosing

When to use it, and when not

Use it when

  • Use it to scan landing buckets that receive files from outside parties, where you cannot fully trust what arrives.
  • Use it when an auditor or privacy officer asks you to prove that personal data is only where the register says it is.
  • Use it to keep an inventory of every bucket's public access, encryption and sharing settings across all accounts in the organisation, at a low per-bucket price.
  • Use it after a migration or acquisition, when a pile of old buckets arrives and nobody knows what is in them.
  • Use it with custom identifiers when your own formats, such as dealer codes or employee numbers, count as personal data.

Avoid it when

  • Avoid scanning every bronze, silver and gold Delta table on a schedule; at a per-GB price, a large lake scanned weekly becomes one of the bigger security bills, and Unity Catalog classification covers tables more cheaply.
  • Avoid treating it as prevention. It finds data after it has landed; tokenising at the door and data contracts with sources stop it from landing.
  • Avoid it for data outside S3, such as databases, streams or SaaS systems; it simply cannot see them.
  • Avoid relying on it alone for free text in local languages; detection is tuned for structured fields and common formats, and recall on names in Hindi or Marathi text is limited.

Production grade

What goes wrong in production

ProblemWhat breaksWhat to do
It cannot read the filesEvery landing object is encrypted with a customer-managed KMS key, and the key policy does not allow Macie, so Macie records only metadata and reports nothing useful.Add a statement to each landing key's policy allowing the Macie service-linked role kms:Decrypt; check the 'unclassifiable objects' counts after the first run.
Bill grows with the lakeSomeone enables automated discovery and broad jobs on every bucket; Macie samples terabytes of Parquet that hold only tokens.Exclude bronze to gold buckets from automated discovery, scope jobs to landing prefixes, and set the monthly analysis quota as a spend cap.
Too many false positivesBuilt-in identifiers flag test data, sample addresses or the company's own phone numbers, and the privacy team starts ignoring findings.Add allow lists, suppress known patterns with suppression rules, and review the top noisy identifiers monthly.
Landing already deletedLanding files with personal data are deleted after one day, so a weekly job finds nothing even when bad data passed through.For sources flagged as personal, run a daily job on the new prefix, or scan a quarantine copy; keep the discovery results as evidence of coverage.
Files too large or unsupportedHuge archives or odd formats are skipped silently, which looks like 'no findings'.Watch the skipped and unclassifiable counts in job statistics; split large exports at the source.
Findings nobody ownsFindings sit in the Macie console where no one looks.Route findings through EventBridge to Security Hub and a ticket queue with a named owner per source, and track time to close.
Multi-account blind spotsMacie is on in the platform account but not in the account where a team created its own landing bucket.Use a delegated administrator account under Organizations and auto-enable Macie for new member accounts.

Cost

How you pay

Macie bills on three meters. Bucket inventory and monitoring is a small monthly charge per bucket. Automated sensitive data discovery adds a charge per object monitored and per GB inspected. Discovery jobs charge per GB inspected, plus the normal S3 GET and LIST request charges. Each newly enabled account gets a 30-day free trial for bucket monitoring and up to 150 GB of automated discovery; jobs are not part of the trial. As a guide, the US East list price is about one dollar per GB inspected (list price, check your region).

What drives the bill

  • Gigabytes inspected, which is almost all of the bill on a data platform.
  • How many buckets and objects automated discovery watches.
  • How often jobs run, and whether they re-scan objects already scanned.
  • The number of accounts with Macie enabled across the organisation.

Cost traps

  • A full job on the whole lake every week rescans the same terabytes again and again; use incremental scheduled jobs that only scan new objects.
  • Automated discovery left on for all buckets samples gold tables full of tokens and finds nothing.
  • Raising the 5 TB monthly job quota without a reason removes your only built-in spend cap.
  • S3 request charges from jobs over many small files can exceed the Macie charge itself.

Prices change; check the AWS pricing page for your region before deciding.

Security and governance

Keeping it safe

  • Macie uses a service-linked role, AWSServiceRoleForAmazonMacie, to read buckets and objects; keep it, and grant it kms:Decrypt on the landing keys only, not on the vault or recipe keys.
  • Findings can reveal samples of the sensitive data itself; restrict the macie2:GetSensitiveDataOccurrences permission to the privacy team.
  • The discovery results repository must be an S3 bucket encrypted with its own KMS key, in the security account, with versioning and tight access.
  • Run Macie from a delegated administrator in the security account, so platform engineers cannot switch it off; an SCP can deny macie2:DisableMacie in member accounts.
  • Every Macie API call is logged in CloudTrail, giving an audit trail of who changed jobs, allow lists or suppression rules.

FAQ

Questions people ask

Does Amazon Macie scan Delta Lake or Iceberg tables?

It scans the Parquet files underneath them as plain files. It does not understand the table, so it scans deleted and old file versions too. For governed tables, classify columns in Unity Catalog instead.

Can Macie read files encrypted with my own KMS key?

Yes, but only if the key policy allows the Macie service-linked role to use kms:Decrypt. Without that, Macie reports only metadata. Files encrypted on the client side or with SSE-C cannot be read.

How much does Amazon Macie cost?

A small monthly fee per bucket, a fee per object monitored by automated discovery, and a fee per GB inspected, which dominates on a data platform. Scope scans to landing buckets and use the monthly quota as a cap.

Does Macie stop personal data from landing?

No. It is a detective control: it reports after the file is in S3. Prevention comes from data contracts and tokenising at the door.

Does Macie detect Indian identifiers such as PAN or Aadhaar?

Yes: there are managed identifiers for Aadhaar, PAN and Indian driving licences, and they need a keyword such as a column name nearby. There is no built-in identifier for Indian phone numbers or Indian postal addresses, and names are found only in Latin script, so add custom identifiers for those.

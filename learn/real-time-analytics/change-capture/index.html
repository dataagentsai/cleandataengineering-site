Change capture: who turns database changes into events

Change data capture tools by source database: Debezium, Qlik Replicate, GoldenGate, Fivetran, Striim, cloud services, what each database needs, and the gotchas.

In plain words

Read what the database already writes

Every database keeps a log of its own changes, so it can recover after a crash. A change data capture (CDC) tool reads that log and turns each change into an event. The app does not change, and the database does very little extra work.

FAQ

Questions people ask

What is log-based change data capture?

A tool reads the change log a database already keeps for crash recovery and turns each insert, update and delete into an event, with no change to the app and little extra load.

Debezium or Qlik Replicate?

Debezium is free and open source and covers the common open-source databases, but you run it. Qlik Replicate is commercial, covers mainframes and SAP, and needs little code. Pick Qlik for many mixed or older sources, Debezium otherwise.

What is the best CDC tool for Oracle?

GoldenGate is the strongest, then Qlik Replicate, Fivetran HVR and Striim. Debezium works through LogMiner or OpenLogReplicator. Check Oracle licensing early: XStream needs a GoldenGate licence.

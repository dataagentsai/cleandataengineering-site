Delta in motion: watch a table change, one commit at a time

A Delta table is just files in a folder plus a log. Press a button and watch exactly what gets written. New data files land first, but nobody can see them until the log entry arrives. Then crash a write, pile up small files, tidy them with OPTIMIZE, and try to time travel after VACUUM.

What just happened

    What each button writes

    Delta never edits a file. Every change writes new files and then adds one line to the log. That one habit gives you transactions, history and safe concurrent readers.

    ButtonNew data filesLog entryWhat to notice
    InsertOne small fileaddMany small inserts mean many small files. Readers must open all of them.
    Update / DeleteThe affected file is rewritten, minus or with the changeremove old + add newThe old file stays on disk. That is how time travel works, and also why disks fill up.
    Tidy small filesOne big file made from many small onesremove all + add oneReaders now open one file. No data changed, only its packaging.
    Clean up the diskNoneNoneRemoved files and crash leftovers are really deleted. Old versions that needed them can no longer be read.
    Insert, then crashOne file, never committedNoneReaders see nothing, so the half-finished write never leaks. The orphan waits for the next clean-up.

    Simplified on purpose: real Delta also writes checkpoints every ten commits, tracks statistics per file, and keeps removed files for a retention period (seven days by default) before clean-up is allowed to delete them. Here, clean-up deletes immediately so you can see the effect.

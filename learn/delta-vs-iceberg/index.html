Delta Lake vs Apache Iceberg, and what differs on Databricks

Delta Lake and Apache Iceberg both turn a folder of Parquet files into a table you can update safely. This page shows how each does it, then the Databricks features that behave differently for each (change data feed, streaming, pipelines, lineage, clustering, masks), and which to pick on AWS.

In plain words

A contents page over the same files

A data lake on its own is a pile of Parquet files. To know which files make up the table right now, which ones were replaced, and what the columns are, you need a contents page. That contents page is the table format. It is what makes updates all-or-nothing, lets two writers work without corrupting each other, and lets you read the table as it was last Tuesday.

Delta keeps its contents page as an ordered diary of changes next to the data. Iceberg keeps it as a tree of metadata files, and a catalog holds the pointer to the current top of the tree. The data files underneath are the same kind of Parquet, which is why Databricks can write Iceberg metadata for a Delta table (UniForm) without copying any data.

Same Parquet files, two different contents pages. The catalog matters more for Iceberg: its pointer decides which version is current.

In short: everything works on managed Delta. Iceberg reads (UniForm) add outside readers without giving anything up, except on streaming tables and materialized views. Managed Iceberg lets other engines write, but today gives up row filters, column masks and keys, and has a change feed only on v3 and only for Databricks readers.

Change data feed

Change data feed (the "enable CDC" switch)

A change data feed lets a reader ask "what changed in this table since version 12?" and get the inserted, updated and deleted rows, instead of re-reading the whole table. Gold builds use it to find which hours changed.

-- Delta: turn it on per table
ALTER TABLE silver.press_readings SET TBLPROPERTIES (delta.enableChangeDataFeed = true);

-- Read the changes since version 12 (batch)
SELECT * FROM table_changes('silver.press_readings', 12);

-- Or as a stream
spark.readStream.option("readChangeFeed", "true").option("startingVersion", 12).table("silver.press_readings")

The same table_changes and readChangeFeed calls work on managed Iceberg v3 tables, where Databricks computes the feed from row lineage.

Outside Databricks, Iceberg has no change feed in its spec; Spark's Iceberg library can build a changelog view between two snapshots, and Flink reads Iceberg changes natively.

Lineage

Two different things called lineage

KindWhat it isUsed for
Data lineageWhich job, notebook or query read which tables and columns to produce which table. Unity Catalog records it for work run on Databricks compute, for any format.Impact analysis, audit, 'where did this number come from'
Row lineage (Iceberg v3) or row tracking (Delta)A permanent id and a version number on every row, kept by the table itself.Cheap change feeds, incremental materialized views, matching a row across rewrites

Unity Catalog lineage is format-neutral but only sees work done on Databricks compute. If Trino or Flink writes a managed Iceberg table through the REST catalog, that write is missing from the lineage graph; record it with OpenLineage from the other engine if you need the full picture.

FAQ

Questions people ask

Is Delta Lake or Iceberg better?

Neither in general. Both put the same Parquet files under a different contents page. Delta is the native format on Databricks and Fabric; Iceberg is the native format on AWS analytics services and Snowflake. On Databricks, keep Delta and turn on Iceberg reads where other engines need it.

Does change data feed work on Iceberg tables in Databricks?

Only on Iceberg v3 managed tables, where Databricks computes the feed from row lineage, and only Databricks readers can use it. Delta tables have it with delta.enableChangeDataFeed = true, or automatically with row tracking.

Can Lakeflow streaming tables be Iceberg?

No. Pipelines write Delta, and Iceberg reads (UniForm) cannot be turned on for streaming tables or materialized views. Compatibility Mode, in preview, can write a read-only copy for other engines.

Does Unity Catalog lineage work for Iceberg tables?

For work run on Databricks, yes. Reads and writes by outside engines through the Iceberg REST catalog are not recorded, so lineage has gaps when other engines write.

What is the difference between data lineage and row lineage?

Data lineage says which job made which table from which tables. Row lineage (Iceberg v3) or row tracking (Delta) gives every row a permanent id inside the table, used for change feeds and incremental updates.

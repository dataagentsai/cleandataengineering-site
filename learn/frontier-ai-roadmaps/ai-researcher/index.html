AI researcher: the roadmap

You ask a question nobody has settled, design a fair test, run it, and publish what you found so others can check it. This page gives you eight small steps, each with a clear finish line, and five small projects. Each project ends in one number you can publish.

The job, in a picture you can hold in your head. A researcher is a scientist whose lab is a computer. They write the guess down first, build the experiment, run it many times, and report honestly, even when the answer is no. The finished product is a short paper, code and data that others can rerun.
This may suit you if: You are patient with hard ideas and happy with slow progress. You like reading carefully, and you care more about being right than about being quick.
Start in 30 minutes: Pick one short paper, write down its claim, its evidence, and what result would have proved it wrong.

Week 0 to 4

First, the base every role shares

Do these five things first. They are the same for all four roles, so nothing you do here is wasted if you change your mind.

StepWhat to doYou are done when
1. Python you can readWrite ten small programs: read a file, count words, call a web API, sort a list of records. Use plain Python, no framework.You can write a loop, a function and a dictionary without looking anything up.
2. Git and GitHubPut every small program in one repository. Commit each change with a one-line message.A stranger can open your repository and run something from the README.
3. Tensors and PyTorch basicsMake a tensor, multiply two of them, take a gradient of one number. Do the first official PyTorch tutorial.You can explain in two sentences what a gradient is for.
4. Run a model on your own machineInstall a local runner (Ollama or llama.cpp) and ask a small open model ten questions.You know the model's size on disk and how many answers per minute it gives.
5. Keep a measurement notebookOne file where every experiment gets: the question, the setup, the number, and what surprised you.Your last three experiments are written down so someone else could repeat them.

The roadmap

Eight small steps

The eight steps in order. Do one at a time; each one is small enough for a weekend or two.

1. Get the maths minimum

One hour a day on vectors, matrices, derivatives and basic probability. Work problems, not videos.

You are done when: You can compute a derivative by hand and multiply two small matrices.

2. Build a neural net from scratch

In plain NumPy, train a tiny network on a toy task such as separating two clusters.

You are done when: You can explain each line of the training loop, including the gradient step.

3. Build a tiny transformer

In PyTorch, train a character-level transformer on a small text file. A public tutorial is fine as a guide.

You are done when: It writes text that looks like the training text, and you can describe attention in your own words.

4. Read one paper a week

Use a fixed template: the claim, the evidence, what would prove it wrong, and what you do not trust.

You are done when: You have four filled templates, one per week.

5. Reproduce one small result

Pick a small, well-known result and rerun it. Record every place your numbers differ from the paper.

You are done when: You can say whether it held up and what the paper left unclear.

6. Ask your own narrow question

Write the guess and the measurement before running anything. Keep the question small enough to finish.

You are done when: Someone else can tell from your note what would count as a yes and what as a no.

Open the matching guide on this site

7. Run it with controls and several seeds

Repeat each experiment with at least five random seeds and report the range, not the best run.

You are done when: Your result includes a spread, and you say if the spread is bigger than the effect.

8. Write it up and ask for feedback

A two to four page note, with code and data public. Send it to one person who works on the topic.

You are done when: A stranger could rerun your code from the page.

Small projects

Five projects, each ending in a number

Keep each project small. Put the code and data in a public repository and write a one-page note on what you found. Where a project has code that can be tested, write the tests as one table of inputs and expected results, with one loop that runs every row. That keeps tests short and easy to extend.

R1. A neural net in NumPy

About one to two weeks

You build
A tiny network, written without a framework.
You learn
What a framework hides: gradients and updates.
Number you publish
Accuracy on a toy task, and the loss curve.

R2. A character-level transformer

About two weeks

You build
A small transformer trained on a text file.
You learn
Attention, training loops and sampling.
Number you publish
Loss curve and a sample of the text it writes.

R3. Reproduce a small result

About two to three weeks

You build
A rerun of one short, well-known paper result.
You learn
What reproducibility really takes.
Number you publish
Your numbers beside the paper's, with the differences explained.

R4. How much do seeds matter?

About one week

You build
The same experiment run with ten random seeds.
You learn
Why one run proves little.
Number you publish
The spread of the result across seeds.

R5. A small measurement of your own

About two to four weeks

You build
One narrow question, such as how a tokenizer treats a language, measured fairly.
You learn
Framing a question, controls, and honest reporting.
Number you publish
One headline number with its spread, and the data released.

What to leave for later

Temptations, with a verdict

TemptationVerdictWhy
Reading every new paperDropOne paper a week, filled in fully, beats thirty skimmed.
Starting with a huge questionDropPick a question you can finish in weeks. Small and finished beats large and abandoned.
Chasing a PhD before any outputDelayMany research roles ask for a PhD or an equivalent public record. Small replications and measurements are how you build that record, whether or not you later enrol.
Using a framework to hide the mathsDelayWrite the first network by hand once. After that, use the tools.

FAQ

Questions people ask

Do I need a PhD?

For many research-scientist roles, yes, or an equivalent public record of original work. Some research-engineer roles value strong engineering plus replications and measurements. Check each posting; this is a pattern, not a rule.

Can I do research without a lab?

Yes, at small scale. Careful replications and measurements, such as the 'small measurement of your own' project, need a laptop and patience, and labs rarely have time for them.

How is this different from LLM engineering?

An LLM engineer makes a system work for a purpose. A researcher answers a question and publishes the answer. The first four steps overlap.

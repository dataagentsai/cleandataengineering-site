Simulation: no guardrails

Six short stories with the guardrails switched off, each laid out turn by turn and ending with what it cost the business. Then switch them on and play it again.

The six stories are illustrations with made-up people and amounts. They are built to show the mechanism. The six incidents further down are real.

How to read this page.Each story is laid out turn by turn, exactly like the loop simulation in stop 4: the request our code sends, the response the model returns, and the tool our code runs. Watch what is inside each request. Rose means harm. Green means a harness check.

What the person sees

What happens behind it

What is prompt injection?

A model reads its instructions and its data as one stream of text. Prompt injection is text that arrives as data and gets treated as an instruction. It can be typed by the user (the second and third stories), or it can hide inside something the agent reads: a document, an email, a web page, a note in a record (the first story). The hidden kind is worse, because the person using the agent did nothing wrong. The last three stories have no attacker at all: an agent with no guardrails can do damage by itself.

The model is not the fix.A better model is fooled less often, and never zero times. In every story with the guardrails on, the model still makes the same mistake. What changes is that being fooled no longer matters, because ordinary code checks every action before it happens.

It has already happened

Six public cases. Most involve assistants far simpler than the agent above.

This is why an agent harness exists.None of the fixes above made the model cleverer. Each one was a piece of ordinary software placed around the model: a fence, a check before a tool runs, a login that limits what a tool can reach, a limit on turns. Put those pieces together and give them a name, and you have the harness.

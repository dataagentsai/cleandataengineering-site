Agent Harness, the big picture

Before any design or any cloud: what kinds of AI application exist, what an agent really does on each turn of its loop, what goes wrong when nothing holds it, and what an agent harness is. Nine stops, one simple picture each, two simulations you can play.

No vendor names on this road. Everything here is the idea; the products come later.

1 · Three kinds of AI application

Every AI application is one of three kinds, and the difference is a single question: who decides the next step? Nobody (there is only one step), your code, or the model. The more the model decides, the more can go wrong, so choose the simplest kind that does the job.

Open stop 1 →

2 · Autonomous agents

An autonomous agent is an agent with less of a person watching it. Businesses want that because work stops waiting for office hours, queues stop growing in a spike, and people spend their time on the cases that need judgement.

Open stop 2 →

3 · Same job, two ways

Ordinary code

Four steps, written by us, in the same order every time. The input is a form.

An agent

One small loop. The model picks each step from what it has seen so far. The input is a sentence.

Both register the same insurance claim. Both are about twenty lines of Python, and both run on the page's own checks.

Open stop 3 →

4 · Simulation: the agent loop

Step through one request a move at a time: the exact request our code sends, the exact reply the model returns, the tool our code runs, and the result going back in. Then watch it stop for one of two reasons: the goal is reached, or the limit is.

Play the simulation →

5 · Simulation: no guardrails

Six short stories with the guardrails switched off, among them a document with hidden orders, a stranger who simply asks for someone else's data, a refund nobody approved and a loop that runs all night. Each ends with what it cost the business. Then switch the guardrails on and play it again. Six real incidents follow.

Play the simulation →

6 · The horse and the harness

The model is a strong horse that does not know the road. The harness is everything that keeps it on the green path: reins, blinkers, a driver and a cart. This is the picture the rest of the course hangs on.

Open the horse page →

7 · What a harness must do

Before the big picture, every requirement by itself: a front door, knowing who is asking, running the loop, calling the model, tools, four kinds of guardrails, logs and traces, cost, evals, safe release, secrets and more. Thirty-three requirements, one small picture each, the way an architect would walk an engineer through them.

Open stop 7 →

8 · The architecture, simple then zoomed in

Five bands and two rails. Then one band, the shared parts, opened up into five families of concerns: Think, Act, Control, See and Change. By now every box in it is a requirement you have already met.

Open stop 8 →

Everything above, in one working agent: a claims assistant that takes the first report of a car accident. Follow one message from start to finish, then send your own in the simulator.

How to read this page

Workloads, compute, rates, and the mapping between them

A Databricks bill is DBUs used × price per DBU, plus your cloud's machine bill on classic compute. Both parts depend on which compute you chose, so the same work can cost very different amounts. This page has four tables: every kind of workload, every kind of compute with its rate, the mapping between them with a monthly example, and what goes wrong in that mapping.

All dollar figures are illustrations. The rates are published AWS Premium list prices in a US region, as summarised by several third-party pricing guides. I did not check the official price list. Azure and Google Cloud differ (one source lists Azure Premium jobs compute at roughly double the AWS figure), contract discounts change the numbers, and DBU rates change. The machine assumptions (2 DBU per hour and $0.384 per hour per machine) are the same ones used on the billing page. Use the tables to compare ratios and mistakes, then redo the arithmetic with your own price list and your own system tables.

How many DBUs per hour

  • SQL warehouses: the size sets DBUs per hour per cluster: 2X-Small 4, X-Small 6, Small 12, Medium 24, Large 40, X-Large 80, 2X-Large 144, 3X-Large 272, 4X-Large 528.
  • Classic clusters: every machine type has its own DBU rating per hour. The cluster rate is the sum over the driver and all workers. A machine of about 2 DBU per hour is a plain assumption for the examples below.
  • Serverless jobs and notebooks: you see DBUs used per run, not machine counts. For the examples below I assume a serverless run uses the same DBUs as an equivalent classic cluster. That is an assumption for illustration, not a published fact.
  • Photon runs at a higher DBU rate. Test whether the speed-up pays for it.

A check you can run each month

  1. For each of your top 10 costs, write down which row of Table 1 it is.
  2. Write down which row of Table 2 it runs on.
  3. If the pair does not match the verdict in Table 3, price the right compute using your own DBU per run and your own rates.
  4. Switch the largest mismatch first, and measure the next month.

Worked decision

Nightly ETL, nobody waiting: serverless Standard mode or a Photon job cluster?

Default to serverless jobs in Standard mode. Use a job cluster only for very large steady work where spot pricing wins, Scala or RDD code, custom images, or private-network access.

Why. Nobody waits, so Standard mode's slow start (typically 4 to 6 minutes, and not billed) costs nothing. It uses fewer DBUs, and Databricks cites savings of up to 70 percent, though the real saving depends on the job. There is no cluster to size, no boot time billed and no VM bill.

When does Photon on a job cluster pay off?

Photon raises the DBU rate, so it pays only if the job gets faster by more than the extra cost. Suppose, as an assumption (I did not confirm the multiplier), that Photon doubles the DBU part. The cluster then costs $4.92 an hour (10 DBU × 2 × $0.15 + $1.92 in VMs) instead of $3.42. It breaks even when the job runs about 1.44 times faster. A SQL-heavy job often clears that bar. A Python-heavy job often does not. Serverless already includes Photon, so this question only arises on the classic side.

On paper, serverless Standard and a classic cluster on spot come out close. The deciding factors are effort and boot time. Run both for a week and compare DBUs per run and the total including VMs. The serverless DBU figure is an assumption (equal to classic), and all rates are illustrative.

What was checked, and what was not

  • The list rates (jobs compute about $0.15, serverless jobs about $0.35, all-purpose about $0.55, serverless all-purpose about $0.75, classic SQL about $0.22, pro SQL about $0.55, serverless SQL about $0.70) come from third-party pricing guides that mostly agree, for example Onehouse and OWOX. They are not from the official price list.
  • The warehouse sizes and auto-stop defaults are from Databricks documentation, and the Standard mode saving is the figure Databricks cites on its performance modes page.
  • The serverless networking limits are from the serverless network security docs.

Not confirmed: the official current rates, serverless pipeline rates, DBU ratings per machine type, the Photon multiplier, whether serverless notebooks offer GPU compute, and how serverless DBU use compares with classic for a given job. Replace every dollar figure with your own before you make a decision.

FAQ

Questions people ask

Why can the same job cost so differently on different compute?

Because the price per DBU depends on the product, and classic compute adds a separate cloud bill for machines. In the examples, the same nightly job costs about 2.2 times more on an all-purpose cluster than on jobs compute.

Is serverless more expensive per DBU?

Yes on paper, because the rate includes the machines. Compare the full monthly cost, including cloud VMs, boot time and idle time on classic.

Which numbers on this page can I rely on?

Use them for ratios and mistakes only. The rates are third-party summaries of AWS list prices, not the official price list, and serverless DBU use is assumed equal to classic.

What is the quickest way to find a mismatch?

List your top 10 costs, name the workload and the compute for each, and check them against the mapping table.

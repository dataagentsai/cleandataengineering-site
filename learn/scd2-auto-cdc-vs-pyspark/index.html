SCD Type 2 on Databricks: AUTO CDC or our own PySpark?

Two ways to keep history of changing records on Databricks: let a Lakeflow pipeline do it with AUTO CDC, or write the MERGE ourselves. This page shows when each is right, for input that arrives as changes (CDC) and input that arrives as full snapshots, with clean code for both and what each costs.

Input is CDC: use AUTO CDC. It handles events that arrive out of order, deletes and duplicate events, which is where hand-written SCD2 code usually goes wrong.
Input is not CDC: if the source is a Delta table you own, turn on its change data feed so it becomes CDC. For true full extracts, AUTO CDC FROM SNAPSHOT is fine for small and medium tables; for very large ones our own hash compare can be cheaper because we choose what to compare.
Write our own when the team runs only plain jobs at high volume, or needs rules AUTO CDC cannot express. Then build one tested SCD2 writer and give each input type a small adapter, never one SCD2 notebook per table.
Cost: the per-DBU gap is usually smaller than the engineering time to own the code. What really moves the bill is how much each run reads, which the input shape decides, not the tool.

In plain words

What SCD Type 2 keeps

A Slowly Changing Dimension Type 2 never overwrites. When a tracked value changes, the current row is closed and a new one opened, and each row says when it was true: valid_from, valid_to, is_current. See the SCD concept page.

One customer, three cities, then a delete. Facts join to the row valid on their own date.

The hard cases every implementation must handle: two changes for one key in the same batch, an older event arriving after a newer one, a "change" that changes nothing we track, a delete, a delete then a re-insert, and a failed batch that runs again.

Clean implementation 1

AUTO CDC in a Lakeflow pipeline

AUTO CDC is the new name for APPLY CHANGES in Lakeflow Declarative Pipelines (formerly Delta Live Tables). The target is a streaming table the pipeline owns; it adds __START_AT and __END_AT from the SEQUENCE BY value.

Input is CDC, in SQL

CREATE OR REFRESH STREAMING TABLE dim_customer
  TBLPROPERTIES ('pipelines.reset.allowed' = 'false');   -- protect history from a full refresh

CREATE FLOW dim_customer_scd2 AS AUTO CDC INTO dim_customer
FROM STREAM(bronze.customer_cdc)
KEYS (customer_id)
APPLY AS DELETE WHEN op = 'D'
SEQUENCE BY commit_ts                          -- or struct(commit_ts, lsn) to break ties
COLUMNS * EXCEPT (op, commit_ts, _rescued_data)
STORED AS SCD TYPE 2
TRACK HISTORY ON * EXCEPT (last_login_ts);       -- noisy columns update in place

Lakeflow pipeline SQL; needs a Databricks workspace, not run on this page.

Input is CDC, in Python

from pyspark import pipelines as dp
from pyspark.sql.functions import col, expr

@dp.view
def customer_cdc():
    return spark.readStream.table("bronze.customer_cdc")

dp.create_streaming_table("dim_customer", table_properties={"pipelines.reset.allowed": "false"})

dp.create_auto_cdc_flow(
    target="dim_customer",
    source="customer_cdc",
    keys=["customer_id"],
    sequence_by=col("commit_ts"),
    apply_as_deletes=expr("op = 'D'"),
    except_column_list=["op", "commit_ts", "_rescued_data"],
    stored_as_scd_type=2,
    track_history_except_column_list=["last_login_ts"],
)

Clean implementation 2

Our own PySpark: one writer, an adapter per input

The writer only understands change events. Planning is a pure function from DataFrames to a DataFrame, so it is tested without Delta; the MERGE is a thin wrapper. Each input shape gets a small adapter.

Three adapters, one planning function, one MERGE.

The writer

"""One SCD Type 2 writer. Input is always change events: key, seq, op ('I','U','D'), tracked columns.
Target columns: key, tracked..., row_hash, valid_from, valid_to, is_current."""
from delta.tables import DeltaTable
from pyspark.sql import DataFrame, Window, functions as F


def row_hash(cols: list[str]):
    return F.sha2(F.concat_ws("|", *[F.coalesce(F.col(c).cast("string"), F.lit("<null>")) for c in cols]), 256)


def plan_scd2(events: DataFrame, target: DataFrame, key: str, seq: str, tracked: list[str]) -> DataFrame:
    """Pure planning step. target = all rows of the SCD2 table (open and closed).
    Returns staged rows for one MERGE:
    merge_key set  = close that key's open row at close_at
    merge_key null = insert this row as a new version"""
    by_key = Window.partitionBy(key).orderBy(seq)
    cur = target.where("is_current").select(key, F.col("row_hash").alias("cur_hash"))
    # Latest point already applied per key, open or closed (a deleted key has no open row).
    seen = target.groupBy(key).agg(
        F.max(F.greatest("valid_from", F.coalesce("valid_to", "valid_from"))).alias("last_seq"))

    ev = (
        events.dropDuplicates([key, seq])
        .withColumn("row_hash", row_hash(tracked))
        .join(cur, key, "left")
        .join(seen, key, "left")
        # 1. Late or replayed events (not newer than what is applied) are skipped.
        #    This makes re-running a failed batch safe, even for deleted keys.
        .where(F.col("last_seq").isNull() | (F.col(seq) > F.col("last_seq")))
        .withColumn("prev_hash", F.coalesce(F.lag("row_hash").over(by_key), F.col("cur_hash")))
        .withColumn("prev_op", F.lag("op").over(by_key))
        # 2. Drop events that change nothing we track.
        .where((F.col("op") == "D") | (F.col("prev_op") == "D")
               | ~F.col("row_hash").eqNullSafe(F.col("prev_hash")))
        # 3. Each version ends where the next event for the same key starts.
        .withColumn("valid_to", F.lead(seq).over(by_key))
    )

    closes = (
        ev.groupBy(key).agg(F.min(seq).alias("close_at"))
        .join(cur.select(key), key)                       # only keys that have an open row
        .withColumn("merge_key", F.col(key))
    )
    inserts = (
        ev.where(F.col("op") != "D")
        .select(key, *tracked, "row_hash", F.col(seq).alias("valid_from"), "valid_to",
                F.col("valid_to").isNull().alias("is_current"))
        .withColumn("merge_key", F.lit(None).cast(events.schema[key].dataType))
    )
    return closes.unionByName(inserts, allowMissingColumns=True)


def apply_scd2(target: DeltaTable, staged: DataFrame, key: str, tracked: list[str]) -> None:
    """One atomic MERGE: close old versions and insert new ones together."""
    cols = [key, *tracked, "row_hash", "valid_from", "valid_to", "is_current"]
    (
        target.alias("t")
        .merge(staged.alias("s"), f"t.{key} = s.merge_key AND t.is_current")
        .whenMatchedUpdate(set={"valid_to": "s.close_at", "is_current": "false"})
        .whenNotMatchedInsert(condition="s.merge_key IS NULL", values={c: f"s.{c}" for c in cols})
        .execute()
    )

Run on Spark 3.5.1 + Delta 3.2.0 on 2026-11-11.

The adapters

from delta.tables import DeltaTable
from pyspark.sql import DataFrame, functions as F
from scd2 import apply_scd2, plan_scd2, row_hash


def run_cdc(spark, source: str, target_name: str, key: str, seq: str, tracked: list[str], checkpoint: str):
    target = DeltaTable.forName(spark, target_name)

    def each_batch(batch: DataFrame, _batch_id: int):
        apply_scd2(target, plan_scd2(batch, target.toDF(), key, seq, tracked), key, tracked)

    (spark.readStream.table(source)
        .writeStream.foreachBatch(each_batch)
        .option("checkpointLocation", checkpoint)
        .trigger(availableNow=True)
        .start().awaitTermination())


def change_feed_events(spark, table: str, starting_version: int) -> DataFrame:
    return (spark.readStream.option("readChangeFeed", "true")
            .option("startingVersion", starting_version).table(table)
            .where("_change_type != 'update_preimage'")
            .withColumn("op", F.expr("CASE _change_type WHEN 'delete' THEN 'D' ELSE 'U' END"))
            .withColumnRenamed("_commit_version", "seq"))


def snapshot_to_events(snapshot: DataFrame, current: DataFrame, key: str, tracked: list[str], snap_ts) -> DataFrame:
    s = snapshot.select(key, *tracked).withColumn("new_hash", row_hash(tracked))
    c = current.select(key, F.col("row_hash").alias("cur_hash"))
    op = (F.when(F.col("cur_hash").isNull(), "I")
           .when(F.col("new_hash").isNull(), "D")
           .when(F.col("new_hash") != F.col("cur_hash"), "U"))
    return (s.join(c, key, "full_outer")
              .withColumn("op", op).where(F.col("op").isNotNull())
              .withColumn("seq", F.lit(snap_ts))
              .drop("new_hash", "cur_hash"))


def run_snapshot(spark, snapshot_table: str, target_name: str, key: str, tracked: list[str], snap_ts):
    target = DeltaTable.forName(spark, target_name)
    rows = target.toDF()
    events = snapshot_to_events(spark.read.table(snapshot_table), rows.where("is_current"), key, tracked, snap_ts)
    apply_scd2(target, plan_scd2(events, rows, key, "seq", tracked), key, tracked)
    # Running the same snapshot twice is a no-op: seq is not newer than what is applied.

def by_key_and_start(row):
    return (row[0], row[2] if len(row) > 2 else row[1])


@pytest.mark.parametrize("name, target, events, closes, inserts", CASES, ids=[c[0] for c in CASES])
def test_plan_scd2(spark, name, target, events, closes, inserts):
    tgt = (spark.createDataFrame(target, "id INT, city STRING, valid_from INT, valid_to INT, is_current BOOLEAN")
                .withColumn("row_hash", row_hash(["city"])))
    ev = spark.createDataFrame(events, "id INT, op STRING, seq INT, city STRING")

    staged = plan_scd2(ev, tgt, key="id", seq="seq", tracked=["city"]).collect()

    got_closes = [(r.id, r.close_at) for r in staged if r.merge_key is not None]
    got_inserts = [(r.id, r.city, r.valid_from, r.valid_to) for r in staged if r.merge_key is None]

    assert sorted(got_inserts, key=by_key_and_start) == sorted(inserts, key=by_key_and_start)

FAQ

Questions people ask

Should I use AUTO CDC or write my own SCD Type 2 MERGE?

If the input is CDC and you can run Lakeflow pipelines, use AUTO CDC: it handles out-of-order events, deletes and duplicates. Write your own when you run only plain jobs at high volume, or need rules AUTO CDC cannot express. Then build one tested writer with an adapter per input type.

How do I build SCD2 from a full snapshot instead of CDC?

If the source is a Delta table you own, turn on its change data feed and treat it as CDC. Otherwise compare the snapshot with the open target rows by a hash of the tracked columns: new keys are inserts, changed hashes are updates, missing keys are deletes. AUTO CDC FROM SNAPSHOT does this for you in Python pipelines.

Is AUTO CDC the same as APPLY CHANGES?

Yes. APPLY CHANGES INTO was renamed AUTO CDC INTO when Delta Live Tables became Lakeflow Declarative Pipelines; the Python function is now create_auto_cdc_flow, and apply_changes_from_snapshot is create_auto_cdc_from_snapshot_flow.

Does AUTO CDC cost more?

On classic compute it needs the Pro pipeline tier, about a third more per DBU than plain jobs compute on AWS list prices. The VM cost is the same, so the total gap is smaller, and often less than the engineering time to own the code. Serverless jobs and serverless pipelines are billed at the same rate.

Can a full refresh delete my SCD2 history?

Yes, for an AUTO CDC target: a full refresh rebuilds from the source, and if bronze no longer holds all events, the history is gone. Set pipelines.reset.allowed = false on the target table.

How do I make a hand-written SCD2 MERGE safe to re-run?

Skip any event whose ordering value is not newer than the latest point already applied for that key, counting closed rows too, so a deleted key is not brought back. The tests on this page cover replay, late events and replay after delete.

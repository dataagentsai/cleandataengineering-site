Streaming simulator: data flow, hop by hop

IoT readings and ordinary sources (app events, database changes, lab files) travel from the source to a live screen in seconds, and through bronze, silver and gold to a Power BI report in minutes. Pick a binding and a route, then break things.

What to try

  1. Watch one 15-minute run. Stream readings pile up at lake ingest; at :00, :15, :30 and :45 a run moves them to bronze and silver. At :15 each hour, gold builds the previous hour and the report updates.
  2. Switch the route to "Direct". The screen stays live, but database changes and lab files have nowhere to go, and no number is ever final.
  3. Switch to "Through the medallion". Every number is governed, but the screen is 15 to 75 minutes behind.
  4. Take a plant gateway offline. The live screen goes stale, the gateway buffers, and when it returns the late readings are counted and the gold hour is marked provisional.
  5. Change the binding. The roles stay the same; only the product in each box changes. On Azure, live Power BI goes through Fabric Real-Time Intelligence.

    FAQ

    Questions people ask

    Is this simulator showing real measured numbers?

    No. It is an illustrative model of the design on the streaming guide: rates, run times and delays are typical values, not recordings.

    Why does the platform lane wait for runs instead of streaming continuously?

    Running every 15 minutes and stopping costs a fraction of an always-on cluster and meets a minutes-level promise. Only the fast lane runs all the time, and it only does light work.

    Can Power BI show real-time data?

    Power BI's old push and streaming datasets are being retired (no new ones after 31 Oct 2027). For seconds-level screens use Fabric Real-Time Intelligence or a live web board; for reports, Power BI reads gold with automatic page refresh.

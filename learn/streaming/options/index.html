Streaming options on AWS at a glance: fast lane and platform lane

Every way we looked at to get streaming data to a screen, in one table: 23 options, 4 recommended. Each row gives the whole path, how fresh the screen is, whether data is pushed or pulled to it, whether it sits in Unity Catalog, rough cost, the verdict and why, and a link to the details.

The short answer: fast lane F1 (AWS-native, 1 to 3 s, ~$530) plus platform lane P2 (chained, 6 to 22 min, ~$770), with P9 for irregular files and P11 for database changes. Switch the fast lane to F6 only if one governed platform is worth the extra cost; add P5 once Lakehouse//RT leaves beta and many users query gold.

FAQ

Questions people ask

What is the recommended streaming design on AWS and Databricks?

Two lanes. The fast lane (F1): Kinesis, Managed Flink, DynamoDB and a WebSocket to a live board, 1 to 3 seconds, about $530 a month. The platform lane (P2): 15-minute Lakeflow runs with gold rebuilt on every run and the gold job starting the Power BI refresh, 6 to 22 minutes, about $770 a month.

When should the fast lane run on Databricks instead?

When having one platform governed end to end in Unity Catalog is worth about $200 to $600 a month more. Then use real-time mode in a serverless Lakeflow pipeline (F6), writing to Lakebase.

Does Lakehouse//RT replace the fast lane?

No. It answers queries in milliseconds but a screen is only as fresh as the table it reads. It fits as the serving layer on gold (P5).

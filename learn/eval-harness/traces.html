Eval Harness Tutorial · From traces

From the agent's traces to a verdict

Most agents already write traces: a record of every piece of work, in a standard format called OpenTelemetry. If we can rebuild conversations from traces, a team adds no code to their agent to be checked. This page follows one real recording through every step.

The recording

A small refund agent built with Pydantic AI, a framework we didn't write, with its own built-in tracing switched on. Its model is scripted, so no AI is called and the recording is identical every time (scripts/record_genai_traces.py). It has three conversations. We follow the one that refunds without looking the order up.

The whole recording is 16 spans. These are the ones for our conversation:

2 · Group spans into conversations

Comes out3 groups, one per conversation

3 · Rebuild the steps

Inside a group, spans are put in time order and turned into steps. The customer's words come from the model's input messages; the replies from its output messages; tool calls and results from the tool spans. Three traps, all found on the real recording, are in how the rebuild works.

4 · Run the rule

The rule: issue_refund needs a successful get_order for the same order_id first.

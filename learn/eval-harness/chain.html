Eval Harness Tutorial · Architecture

The whole chain: from agent code to a dashboard

An agent does its work, writes down what it did, and that record travels to a tool where people look at it. The eval harness sits along that road. This page draws the whole road once, top to bottom, so you can see where each part of the framework stands and which parts are tools you already have.

Read the colours as a status report. Blue is a tool that already exists and isn't ours. Green is ours and built. A dashed white box is ours and not built yet.

The five rows, in plain words

RowWhat happens thereSame on every platform?Our part
1 · Agent harnessThe agent loops: ask the model, call a tool, repeat, reply. A check can step in at five moments. Every step is written down as a span.YesInline checks: built. The loop and the telemetry are the agent's own.
2 · What leaves the agentSpans in the OpenTelemetry GenAI format, plus two kinds of event from us: what a rule decided, and what a check found.Yes. This is the first fixed contract.Verdict events and decision events: built.
3 · Where it landsThe client's trace store. Beside it runs the eval worker: it reads the traces, rebuilds each conversation, runs the rules and writes verdicts back into the same store.No. Each store has its own query language.One reader per store. App Insights is run live; CloudWatch and Phoenix are built and wait for a live run; the rest are not built.
4 · The common questionsOne list of what ops asks of any agent. Each question becomes a definition, and a small query writer turns it into the store's language.The list and the definitions, yes. The query writer, no.62 questions: 8 answered, 4 partly, 50 not yet. Definitions are the next thing to build.
5 · What people seeThe client's own screens. We ship what goes on them: a report, a dashboard template, alert rules.The content, yes. The screen is theirs.Weekly report: built. Dashboard templates and alerts: not built.

Prometheus sits in row 3 as an optional second store for totals. Some platforms keep detail and totals in one store, others in two: see one store or two.

Why two contracts make it reusable

The middle of the chain can't be generic, because Azure, AWS and Databricks each store traces their own way. So we fix the two ends instead. Row 2 fixes what goes in. Row 4 fixes what is asked. Between them, a platform needs only a reader, a writer and a query writer.

What every agent gets, and what each agent still writes

The framework does the parts that are the same for every agent. A team adds only what the framework can't know: the agent's own tools, limits and rules.

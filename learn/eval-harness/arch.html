Eval Harness Tutorial · Architecture

Where the framework fits

This is what we're trying to do, in one drawing. Your agent and the tools around it stay as they are. The framework (the dark box) plugs in at four points, numbered below, and writes its verdicts back into tools your team already uses. It has no database, dashboard or chat window of its own.

The four ways in, in plain words

#WhereWhenCan it stop a bad reply?
1Hooks inside the agent's frameworkDuring the turn: inlineYes
2The gateway every model call passes throughDuring the turn: inlineYes, for model calls only
3The traces the agent already writesAfter the turn: onlineNo: it alerts and reports
4Golden test sets, CI, historyBefore release or in batch: offlineIt stops a release, not a reply
What's built today

The engine's check step, the five patterns, four provider checks, and reading traces from a trace file (way 3). The reference agent's own harness already runs checks inline (way 1) using this package. Running any check at the gateway, inline in other frameworks, and writing results back are planned: see every integration.

When checks run: offline, inline, online

The same check can run at three different times. Which one you pick decides what the check can do about a problem.

  • Inline runs during the turn, before the customer sees anything. It can block, redact or hand over. It must be fast, because the customer is waiting.
  • Online runs after the turn, on real traffic, usually a sample. It can't undo a reply, but it can alert, open a review and spot trends. It can take seconds, so AI judges are fine here.
  • Offline runs before release or in batch: on golden test sets in CI (a fail blocks the release), re-running new rules over old traces, and cost rules that need days of data.

Each check declares its speed

Every check states how fast it is, and the framework refuses to put a slow check in a fast place. Measured: DeepEval's “deterministic” check takes about 500 ms, so it's online, not inline; Presidio takes about 2 s on its first call, so an inline host must warm it up.

Power BI and Fabric, in depth

How the new Fabric-based Power BI works, what happens inside a query, how it handles volume and row-level security when the data is in a Databricks lakehouse, and how to troubleshoot, benchmark and test it before production.

The new Power BI

How Fabric works

Power BI is now one part of Microsoft Fabric. Fabric is a software-as-a-service data platform: you do not run servers, you buy a capacity and every Fabric workload spends from it. Power BI Premium capacities (P sizes) have been replaced by Fabric capacities (F sizes).

One capacity, many workloads, one lake. Power BI is the reporting workload on top.

IdeaWhat it means
CapacityYou buy a capacity size (F2 up to F2048). Every Fabric job, including Power BI queries and refreshes, spends capacity units (CU) from it.
SmoothingShort spikes are spread out: interactive work (report clicks) over at least 5 minutes, background work (refreshes) over 24 hours. You pay for the average, not the peak.
ThrottlingIf you keep borrowing from the future: after about 10 minutes of overuse, report clicks are delayed; after about 60 minutes, they are rejected; after 24 hours, refreshes are rejected too. Watch it in the Fabric Capacity Metrics app.
LicencesBelow F64, every viewer needs a Pro (or Premium Per User) licence. From F64 up, viewers with a free licence can read content; authors still need Pro.
OneLakeOne data lake per company, storing tables as Delta Parquet. Shortcuts point to ADLS, S3 or GCS without copying. Mirroring brings other databases in, including Azure Databricks Unity Catalog catalogs.
WorkspacesFolders of items (semantic models, reports, lakehouses) with roles: Admin, Member, Contributor, Viewer. Only Viewers are held by RLS.

Internals

Inside a Power BI query

Every visual sends a DAX query. Two engines answer it.

VertiPaq, the in-memory engine, stores each column separately. It replaces each distinct value with a small number (dictionary encoding) and stores runs of the same number once (run-length encoding). So a column with few distinct values (country, status) shrinks enormously, and a column with millions of distinct values (timestamps to the second, GUIDs, free text) barely shrinks. Cardinality decides model size and speed.

The formula engine works out what the DAX means and runs on one thread. The storage engine scans compressed columns on many threads, or, in DirectQuery, turns the request into SQL for Databricks. Both cache results, which is why the second run of a query is faster (test both cold and warm).

Volume

Storage modes and how volume is handled

Where the data sits decides speed, freshness, cost and whether Unity Catalog security applies.

Security

How row-level security works in Power BI

A role is a DAX filter on a table, written in the model. When a user opens a report, Power BI adds the filter for each role the user belongs to, and the filter flows along relationships from the 'one' side to the 'many' side. Several roles add up (a user in North and South roles sees both). Members are assigned in the service, ideally as Entra ID groups.

KindHowCatchVerdict
Static roleA DAX filter with a fixed value, e.g. [region] = "North"; one role per region.Many roles to maintain; grows badly.Drop beyond a handful
Dynamic roleOne role; the filter compares a column with USERPRINCIPALNAME() through an entitlements table.Needs the entitlements table and a single-direction relationship from it.Pursue
Object-level security (OLS)Hides whole tables or columns from a role (e.g. salary).Reports that use the hidden column break for that role.Pursue for sensitive columns
Embedded, 'app owns data'Your app passes an effective identity (user name and roles) in the embed token.Your app must pass the right identity every time.Pursue for customer-facing embedding
DirectQuery with single sign-onThe user's Entra ID identity is passed to Databricks, so Unity Catalog filters apply as well. Simple on Azure Databricks; on AWS and GCP check current OAuth support.Both rule sets apply; the user sees the overlap.Pursue for sensitive, fresh data

When it is slow

Troubleshooting Power BI performance

SymptomTool to find the causeUsual fixes
A report page is slowPerformance Analyzer in Power BI Desktop: time per visual split into DAX query, visual display and other.Copy the slowest visual's DAX into DAX Studio.
One DAX query is slowDAX Studio with Server Timings and the query plan: formula engine vs storage engine time, number of storage engine queries.High formula-engine time: rewrite the DAX (iterators over big tables, nested CALCULATE). Many storage-engine queries: simplify the model or measure.
The model is big or refresh runs out of memoryVertiPaq Analyzer (in DAX Studio or Tabular Editor): size per table and column, cardinality.Drop unused columns; split date and time; remove high-cardinality IDs and GUIDs; turn off auto date/time; prefer measures to calculated columns.

Benchmarking

How to benchmark Power BI

  • Set a budget first: for example, every page renders in under 3 seconds at the 95th percentile, with 50 people using it at once, and costs under a set number of capacity units.
  • Single query: DAX Studio's benchmark runs a query several times with a cold cache and a warm cache and reports both. Record the storage-engine and formula-engine split.
  • Whole page: Performance Analyzer, exported as JSON, gives the time per visual. Keep the file per release to compare.
  • Many users: Microsoft's Realistic Load Test Tool replays report sessions in browsers; watch the Capacity Metrics app (CU and throttling) and, for DirectQuery, the Databricks warehouse (queueing, clusters, p95 latency).
  • Same data, every run: benchmark on a fixed copy of production-sized data, otherwise you compare data growth, not changes.

FAQ

Questions people ask

How does Direct Lake work with data in Databricks?

Direct Lake reads Delta Parquet files in OneLake into memory. Databricks data reaches OneLake through a shortcut to its storage or through a mirrored Azure Databricks catalog. Unity Catalog row filters and masks do not apply to those file reads, so secure the data in Power BI or OneLake, and expect slower loads because Databricks does not write V-Order.

Why is my Power BI report slow?

Find the slow visual with Performance Analyzer, then the slow part with DAX Studio Server Timings. Formula-engine time means the DAX needs rewriting; storage-engine or SQL time means the model, the data size or the source is the problem.

How do you test Power BI?

Keep the model as code (PBIP and TMDL in git), run Best Practice Analyzer in CI, test each measure against the source (same-number test), test RLS with impersonated users, refresh in a test workspace, and benchmark key queries before release.

Does Power BI RLS apply to workspace members?

No. Admins, Members and Contributors of the workspace see all rows. Only users with the Viewer role, or app audiences, are filtered.

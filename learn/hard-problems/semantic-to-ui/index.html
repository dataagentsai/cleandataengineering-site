Semantic to UI: hard problems and anti-patterns

The hard challenges and common anti-patterns of semantic to ui in a data platform, with how each is solved and tested. This hop must serve dashboards, conversation interfaces, agents and apps the same certified numbers, cheaply and visibly fresh.

Where we are

Semantic to UI

What this hop must achieve. Serve dashboards, conversation interfaces, agents and apps the same certified numbers, cheaply and visibly fresh.

This is a hop: the step that moves data from one layer to the next. Handled by: semantic layer generators, observability, agents, the platform app.

The hard part

7 challenges, and how they are solved

Every example comes from the tyre world, a synthetic tyre company whose fourteen simulated days carry planted problems with known right answers, so each fix is tested, not just described.

What not to do

Common anti-patterns

An anti-pattern is a habit that looks reasonable and keeps causing the same damage. These are the ones seen most often at this hop.

Anti-patternWhy it hurtsDo this instead
Business logic in BI tools or viewsThe same metric gets computed differently in each dashboard, and nobody can test it.Put calculations in gold build() or in the semantic layer's metric definitions.
Pointing a conversational query tool at raw silver tablesThe tool then guesses joins and meanings and gives plausible but wrong answers.Point it at metric definitions and described gold tables.
Agents querying tables directlyUntested, unpermissioned queries; answers that differ from the dashboard.Typed tools over certified definitions, with proposals going to a gate.
A custom portal that rebuilds native dashboardsTwice the work, and it drifts from the governed screens.Link out to native screens; build only screens that take actions.

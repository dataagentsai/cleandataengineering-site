Limitations to know before you decide

Checked against vendor documentation on 21 November 2026. Where two documents disagreed, the table says so. Treat each row as "confirm this on your runtime and region before relying on it".

Databricks side

UniForm (Iceberg reads of Delta)Iceberg clients are read-only. Column mapping is required. Iceberg v2 reads do not work on tables with deletion vectors (Iceberg v3 supports them). Iceberg reads cannot be enabled on materialized views or streaming tables. Parquet files use Zstandard instead of Snappy. Delta Sharing recipients read the table as Delta only.Databricks: read Delta tables with Iceberg clients
Managed Iceberg tables in UCReports of general availability in 2026 conflict with pages that still say preview, so check your cloud. Listed limits: needs runtime 16.4 LTS or later, no primary or foreign keys, no partitioning by expressions such as bucket() or days(), partition evolution only through external engines on the Iceberg REST catalog, external engines cannot read UC views, Parquet only, some nested and special types unsupported, no credential vending on default storage. The documentation also says creating them needs Predictive Optimization enabled.Databricks: Apache Iceberg
Predictive OptimizationUC managed tables only. It does not run on streaming tables, materialized views, external tables or tables shared in by Delta Sharing. Needs the Premium plan and a supported region. Billed as a serverless jobs SKU. Older pages say it skips tables using Z-order or liquid clustering, newer ones describe automatic liquid clustering, so the docs differ by version.Databricks: predictive optimization
Liquid clusteringAt most four clustering keys. Cannot be combined with partitioning or Z-order. Clustering on write only happens above a size threshold (for example 64 MB with one key, 1 GB with four). Automatic key selection needs runtime 15.4 LTS or later and UC managed tables.Databricks: liquid clustering
Serverless computeOnly Spark Connect APIs: no RDD APIs, no sparkContext, no global temporary views, no compute policies. Maximum run time 7 days. Streaming triggers such as continuous and processing-time are not supported, so use available-now. Sources differ on Scala and R support, so check the current page.Databricks: serverless limitations
Declarative pipelines and Auto CDCIdentity columns are not supported on Auto CDC targets. A dataset can be defined only once across pipelines (append flows into a streaming table are the exception). pivot() is not supported. A workspace allows 1,000 concurrent pipeline updates.Databricks: pipeline limitations
LineageThe lineage system tables keep a rolling one-year window and hold only a subset of events, recorded when lineage can be inferred. Column lineage needs both source and target referenced by table name. Only events from UC-governed work (pipelines, notebooks, jobs, SQL, dashboards) appear, so mixing governed and ungoverned compute leaves gaps.Databricks: lineage system tables
Metric viewsThe main docs say metric views do not support lineage, Delta Sharing or Lakehouse Monitoring. In Power BI, the BI compatibility mode needs DirectQuery, a recent Desktop build, and cannot join a metric view to other tables. One Microsoft page says that mode was removed from the connector while a Databricks page calls it Beta, so confirm the status.Databricks: Power BI and metric views, Microsoft: BI metric view

What this changes in the comparison. Four things matter most for the decision. (1) Managed Iceberg tables in UC are tied to Predictive Optimization, so "Iceberg on Databricks" is not independent of the managed stack. (2) UniForm stays read-only, so a multi-writer design must be Iceberg-native. (3) Fine-grained Lake Formation on EMR works but with a long list of conditions, so test your exact EMR release and mode. (4) Power BI on metric views is the least settled part of the Databricks story, so pilot it before promising it.

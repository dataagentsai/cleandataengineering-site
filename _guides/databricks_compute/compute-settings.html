The map

Every kind of compute, in one table

Three words that are not the same thing. Classic vs serverless says who runs the machines: you (in your cloud account) or Databricks (in its account). All-purpose vs jobs vs SQL warehouse says what the compute is for. Interactive is just a way of working, typing in a notebook, and is not a product. So an all-purpose cluster is a classic cluster used for interactive work. A job cluster is also classic, but it is not all-purpose. A serverless notebook is interactive, but it is not classic.

There are three families: SQL warehouses (for SQL and BI), jobs compute (for scheduled work) and all-purpose compute (for interactive work). Each exists in a classic form that runs in your own cloud account, and most have a serverless form that runs in Databricks' account.

Yes, classic warehouses still exist. I found no deprecation notice. The three warehouse types are serverless, pro and classic. For choosing between them, see choosing compute. This page is the settings reference: what each setting does, what to set and what people set wrongly.

Server types

Node types: which machine for which problem

On AWS, Databricks node types follow the EC2 families. Other clouds have equivalents with different names. Databricks also offers fleet instance types, which can draw from several similar machines to reduce capacity errors.

FamilyUse it whenNotes
General purpose (m-family, fleet: md-fleet)You are unsure, or the job is balancedA safe starting point
Memory optimized (r-family, fleet: rd-fleet, rgd-fleet)The Spark UI shows spill to disk, wide joins, or big aggregationsOften better than adding more general-purpose nodes
Compute optimized (c-family)The job is CPU-bound and does little shufflingToo little memory for large joins
Storage optimized (i-family)Read-heavy and interactive work that benefits from local SSD and the disk cacheI did not find a Databricks fleet type for this family
GPU (g and p families)Model training and some inferenceNot available as fleet types. Pick a specific GPU type, usually on dedicated access mode.
Graviton (Arm)Plain batch jobs, to cut the VM priceDocumented as unsupported for Databricks SQL, declarative pipelines and Container Services. Python UDFs need runtime 15.2 or later. Not offered as a fleet type.
  • A d in the name (for example md-fleet) means local SSD, which the disk cache uses.
  • When the worker type is a fleet type, the spot bid percentage has no effect.
  • Single node compute runs everything on the driver. Use it for small exploration, not for jobs that need to scale.

All-purpose

All-purpose compute: access modes and the usual mistakes

  • Standard access mode (formerly called shared) supports Python, SQL and Scala on recent runtimes, and Databricks recommends it for most workloads. It has limits: no R, no Hive UDFs, no sc or sqlContext in Scala.
  • Dedicated access mode (formerly single user) is for RDD APIs, GPUs, R and privileged machine access.
  • Auto-termination: a value of 0 in a policy means never. I could not confirm the default for all-purpose compute, so check it in your workspace.
MistakeWhy it hurtsFix
Auto-termination off or set to many hoursAn idle cluster bills all night and at weekendsA policy that forces a short auto-termination
A big cluster for a notebook that reads a small tablePays for unused coresSingle node, or serverless notebooks
Scheduled jobs left on an all-purpose clusterHigher DBU rateMove to jobs compute or serverless jobs
Dedicated mode by defaultFewer users per cluster and more clustersStandard unless you need RDD, GPU or R
No cluster policyAnyone can launch an expensive clusterPolicies that cap size, force tags and set auto-termination

Find the wrong settings in your own workspace

SELECT cluster_id, cluster_name, auto_termination_minutes, worker_node_type, min_autoscale_workers, max_autoscale_workers FROM system.compute.clusters WHERE delete_time IS NULL ORDER BY auto_termination_minutes DESC NULLS FIRST

Column names here are from memory and may differ in your workspace, so check the table's schema first. Run it against a small copy, as explained on the system tables page.

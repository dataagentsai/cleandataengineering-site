Backup and recovery

Best architecture for backup and recovery

Start with the surprise: Delta time travel is not a backup. It lives in the same storage as the table, and VACUUM deletes old files by design (history is kept for a limited time, often a week). Time travel is a fast undo. A backup is a separate copy that an attacker or a bad script cannot touch.

The design rules

  1. Decide RPO and RTO per data set. RPO is how much data you can afford to lose, RTO is how long you can be down. Most tables do not need DR. A few do.
  2. Everything that can be code is code. Workspaces, catalogs, grants, jobs, warehouses and policies in Terraform or Asset Bundles, kept in Git.
  3. Backups live in a different account with different credentials. Production may write, but never delete. Turn on immutability.
  4. Use Delta-aware copies. Deep clone is incremental, copies data and log together, and is consistent.
  5. Unity Catalog metadata is in the control plane. Back up its definitions (catalogs, schemas, grants, external locations) through Terraform or API exports, because the data copy alone does not recreate permissions.
  6. Practise the restore. A backup you have never restored is a hope. Schedule a restore drill and time it.
  7. Mind the bill. Cross-region copies cost transfer fees (see cross-region cost) and storage. Back up gold and critical tables, not every scratch table.

Sharing and regions

Delta Sharing: does it help, and how it works inside

How it works

Delta Sharing is an open protocol. The data owner (provider) publishes a share that lists tables. A reader (recipient) gets a credential, or for Databricks to Databricks, a trust link inside Unity Catalog. The key idea: the sharing server hands out short-lived signed links to the Parquet files, and the reader downloads straight from cloud storage. The server never carries the data.

  • Table versions. The server reads the Delta log to know which files make up the current version, or a past version, and which files can be skipped using min/max stats.
  • Two flavours. Databricks to Databricks uses Unity Catalog trust and needs no token. Open sharing gives other tools a token or federated identity.
  • Limits you set. You can share a table, a view or a partition slice, and use dynamic views for row and column filtering.

Does it help with system table cost?

It helps indirectly, and only in one pattern. It does not make the original system tables cheaper to read. It helps when you build one central FinOps workspace, create the small rollup table there, and share the rollup to other workspaces, regions or accounts. Each BU then reads the small shared table instead of running its own heavy system table queries.

Sharing and regions

Cross-region cost, and how to avoid it on Databricks

You are right that moving data between regions costs money. The cloud providers charge for data leaving a region (and sometimes between availability zones), while data moving inside a region between compute and storage is normally free. Databricks does not add this fee. It is a cloud provider charge that appears on a cloud invoice (or on the Databricks one for serverless networking). Check your provider's current rates, but the order of magnitude is a few cents per gigabyte.

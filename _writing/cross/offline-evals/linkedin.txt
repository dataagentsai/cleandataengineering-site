Your agent's average score went up, so you shipped it. Then refunds broke, because one slice got worse and the average hid it. Here is how to build offline evals that block a bad release: golden sets, scenarios, code checks before judges, and a baseline that is the last release, not perfection.

An agent can be wrong without throwing a single error, so you need a test it must pass before every release. Build a golden set of cases with known right answers, play whole conversations against a simulated world, judge each case with code first and an LLM judge only where code can't see, compare with the last release slice by slice, and turn every production failure into a new case.

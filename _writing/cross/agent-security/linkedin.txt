Most agent security plans are a paragraph in the system prompt and one service account that can do everything. That account is a master key handed to a program that believes whatever it reads. Here is the architecture we use instead, with one real run where the model was fooled and nothing moved.

An agent that can call tools holds keys to real systems, so the question is whose keys and how many. It should act as the signed-in user, see only the tools that user may use, and meet a second check at the system it calls. Treat everything a tool returns as data, keep secrets out of prompts, and make sure what serves traffic is what you tested.

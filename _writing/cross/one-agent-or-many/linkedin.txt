A "team" of five agents looks great in a demo. In production it means five hand-offs that drop details, a bill that multiplies, and agents politely passing the same task back and forth. Here is when multi-agent really helps, when one agent with good tools is better, and five safety rules if you do split.

Splitting work across several agents looks tidy on a whiteboard, but every hand-off loses context, every conversation between agents costs money, and every extra agent is one more thing to trace and test. Go multi-agent when permissions, skills, parallel work or sheer size truly demand it. Otherwise, one agent with a router and good tools does the job better.

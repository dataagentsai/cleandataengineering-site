Vertical agents · Logistics and freight

Vertical agents for logistics and freight

Every shipment produces exceptions: delays, damage, missing paperwork. Agents spot them early and handle the routine ones.

Products we connect to

The products

Most businesses in this industry run on one of these. Each agent gets a connector for each of them, and we build first against the products that give developers a sandbox, meaning a test copy of the product we can use without a customer.

One harness under all of them

How we build them

Same harness, different industry

  1. Code first, model second. If a rule can decide something, such as a refund limit or a lab value outside its allowed range, code decides it. The model handles the language.
  2. People approve anything risky. Money, promises to customers and clinical or legal decisions always wait for a named person.
  3. Each product is a connector. The agent talks to one interface. OPERA, Apaleo and Mews are three plug-ins behind it, so moving to another product means swapping the plug-in, not rebuilding the agent.
  4. Tested in a simulated world first. Every agent passes a simulated week, with difficult customers, slow systems and failures, before it meets a real one. See AgentTwin.
  5. Checks you can see. Every guardrail comes from the guardrail catalog, and every agent's cost per conversation is measured.

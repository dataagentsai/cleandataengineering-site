Data project essentials: the 6-week programme

How non-technical roles learn to run a data project: 12 sessions in seven parts over 6 weeks, 12 h 30 min of live time. No code. Each week you go deeper on your own and build something on your own project.

Why

Purpose of the programme

In one line: every non-technical role on a data project should know what to ask, what to write down and what to check, and should work the same way: Agile, spec first, everything in git, with AI as a helper.

Speak one language

Everyone on a data project uses the same picture, the same ten stages and the same words, so hand-offs between BA, Tech Anchor and PM stop losing meaning.

Ask the right question early

Each role knows what to ask at each layer and which early sign points to which failure, while it is still cheap to fix.

Work one way

One backlog in slices, a written spec before any build, and every document in git with history and review.

Use AI safely in every function

BA, PMO and delivery use an AI assistant for first drafts and checks, and know how to verify the result.

Leave with reusable assets

Skills such as the estimator and the project review, and a starter kit of templates that the next project copies.

How we will know it worked

  • Every attendee has filled the core templates for a real project.
  • Every attendee has built and shared at least one skill for their role.
  • The team has one project repository layout that new projects copy.
  • Estimates are given as ranges with assumptions, from the same estimator.
  • Reviews use the same checks and the same four ratings.

Part E

Everything in git, so AI and spec-driven development can work

An AI assistant can only help with what it can read. If requirements are in emails, decisions in chat and the backlog in a slide, it reads none of them. When every document is a text file in one repository, a person or an AI assistant can read the whole project, a spec can drive the build and the test, and every change has an author, a reason and a reviewer.

WordWhat it means, without the jargon
RepositoryThe project's shared folder. It keeps every version of every file.
CommitA saved change, with a short note saying why.
BranchYour own copy to work in, so the agreed version stays as it is.
Pull requestA proposed change that someone else reads before it is accepted.
HistoryWho changed what, when and why. It is also the audit trail.

FunctionWhere AI helpsWhat a person must still check
Business analysisDraft the questions for a source meeting. Turn notes into a spec. Draft a metric definition. Find requirements that cannot be tested. Draft a mapping.Every definition with its business owner. Every figure against the source.

Five rules for using AI at work

  1. You own the answer. The AI assistant drafts; a named person checks and signs.
  2. Give it the template, the spec and the context. A vague request gets a vague answer.
  3. Ask where each statement came from. No source, no trust.
  4. Client data, personal data and secrets do not go into a tool the client has not approved.
  5. Keep the request, the result and your correction in git, so the skill improves.

FAQ

Questions people ask

Is this for technical people?

No. It is for business analysts, project and delivery managers, PMO, product owners, testers and sponsors. There is no code. Git is taught as a shared folder with history and review.

How much time does it take?

Two live sessions a week for six weeks, an hour each, and about two hours a week on your own to read deeper and build.

What is a skill here?

A short written instruction, a template and a checklist that an AI assistant follows the same way every time. For example the estimator for data projects, or the project review.

Do I need my own project?

It helps. Every exercise is done on a real project. If you have none, use a past project you know well.

Can we run it faster?

Yes. The twelve sessions fit a three-day workshop, four sessions a day, with the building done afterwards on your own project.

Where are the fifteen roadmap topics?

They are all still covered. Each session says which roadmap topics it covers, and the deeper reading is done on your own.

Topic 8 · Deep dive

Extracting knowledge from people and systems

What to find out about a source system and its consumers, from whom, how, with what access, with AI as an assistant, and what goes wrong if you do not. Twenty-two things to extract, each with what happens when it is missing, how to get it, and the precautions.

Teach first

Knowledge lives in four places

Look at it from two directions. Upstream is the systems the data comes from. Downstream is the reports and applications that use it. In each direction, knowledge sits in people's heads and in the systems and artefacts, such as code, reports, tickets and logs. AI can speed up all four, but it never replaces the owner saying 'yes, that is right'.

Four places to look. People and systems often disagree, and the disagreement is the finding.

The rule: measure facts with queries, let AI draft and explain, and have the owner confirm. Never the other way round.

Each in detail

What, why, if missing, from whom, how, AI, access, precautions, what goes wrong

Group A

Meaning and structure

1Business meaning of fields, codes and statuses Upstream and downstream Must

What to extract
What each field, code and status means, in business words.
Why it matters
Every number depends on it.
If we do not have it
Wrong joins and filters. Numbers disagree with finance. Rework in the last weeks.
From people
Source owner, business owner, long-serving users.
From systems
Data dictionary, lookup and code tables, screen labels, column comments.
How
Walk through the real screen and the real table side by side. Read the lookup tables. Compare labels with column names.
How AI helps
Drafts a glossary from column names, comments and sample values, and proposes meanings for codes. Limit: Sounds right and may be invented. Mark 'inferred' until the owner confirms.
Access needed
Metadata read, a sample extract, demo access to the application.
Precautions
Do not paste real customer values into unapproved AI. Confirm each code in writing.
What can go wrong
One code reused for two meanings over the years. An AI guess accepted as fact.
Backlog items
SRC-02 SRC-10 PRJ-16

2Relationships between tables and entities Upstream Must

What to extract
How tables relate: one-to-many, many-to-many, optional links, orphans.
Why it matters
Joins define every report.
If we do not have it
Rows duplicated or lost on joins. Wrong totals.
From people
Source developers, database administrators, power users.
From systems
Declared foreign keys, ER diagrams, query logs, application code models.
How
Read declared keys. Infer undeclared links by name and by value overlap, meaning what share of values in table A exist in table B. Read frequent joins from query logs. Count orphans.
How AI helps
Suggests likely links from names and descriptions, and explains an ER diagram in plain words. Limit: Similar names mislead. Overlap must be computed, not guessed.
Access needed
Metadata read, a read-only query on a replica, query logs.
Precautions
Overlap queries scan big tables. Sample them and run off-peak.
What can go wrong
An undeclared relationship is missed. A many-to-many treated as one-to-many inflates totals.
Backlog items
SRC-03 SRC-10

3Keys Upstream Must

What to extract
What uniquely identifies a record: technical IDs, business keys, composite keys. Are keys reused or changed?
Why it matters
Deduplication, updates, history and joins all rest on keys.
If we do not have it
Duplicates. Lost updates. History attached to the wrong record.
From people
Source owner, database administrator.
From systems
Primary and unique constraints, index definitions, uniqueness measured on real data.
How
Read constraints. Test uniqueness on real data. Test stability: does a key change over time? Check reuse after deletion.
How AI helps
Proposes candidate keys and explains composite keys. Limit: Unique today is not a promise for tomorrow.
Access needed
Metadata read, read-only query on a replica.
Precautions
Test across the full history, not the last 30 days.
What can go wrong
Keys recycled after a delete. A key that is unique only within a region.
Backlog items
CLN-01 CLN-07

4Constraints and rules Upstream Should

What to extract
Declared and hidden limits: mandatory fields, allowed values, ranges, formats, referential rules, rules enforced only in the application.
Why it matters
They define what 'valid' means.
If we do not have it
The pipeline rejects good rows or accepts bad ones.
From people
Source owner, testers.
From systems
Schema constraints, check constraints, triggers, validation code in the application.
How
Read the table definitions. Compare with the data: violations show a rule that is not enforced. Read the validation code.
How AI helps
Summarises validation code and triggers into plain rules. Limit: Misses rules in other layers.
Access needed
Table definition read, code repository read.
Precautions
Rules on paper and rules in the data differ. Always test against data.
What can go wrong
A constraint exists but is switched off, and the data breaks it.
Backlog items
CLN-02 CLN-03

5System flow Upstream and downstream Must

What to extract
How data enters, moves and leaves the system: interfaces, jobs, order, dependencies, manual steps.
Why it matters
It shows what depends on what.
If we do not have it
Surprise feeds. Wrong load order. Hidden manual fixes.
From people
Source owner, operations and support, integration team.
From systems
Job scheduler, integration platform, API specifications, run logs, network diagrams.
How
Draw the flow with the owner. Read scheduler definitions and run logs. Trace one record end to end.
How AI helps
Turns scheduler settings and scripts into a draft flow diagram and dependency list. Limit: Cannot see manual steps or undocumented jobs.
Access needed
Scheduler read, log read, repository read.
Precautions
Read-only. Never trigger a job.
What can go wrong
A manual file upload at midnight that nobody mentions.
Backlog items
SRC-05 RUN-01

6Transactional (OLTP) or analytical (OLAP) Upstream Must

What to extract
Is the source transactional (many small writes, current state, normalised) or analytical (history, aggregated, read-heavy)?
Why it matters
It decides the loading method and the risk to the source.
If we do not have it
Heavy queries slow a live system. Wrong expectations about grain and history.
From people
Database administrator, architect.
From systems
Database type, workload statistics, indexes, replicas, table design.
How
Ask workload questions. Read database statistics. Check for a read replica or a warehouse. Look at the design: normalised tables or a star shape.
How AI helps
Classifies tables as transactional or analytical from their structure and describes load risks. Limit: Needs workload data to confirm.
Access needed
Database metadata, performance statistics.
Precautions
Never run big scans on a live transactional primary.
What can go wrong
A profiling query on the production primary slows the application.
Backlog items
SRC-08 LND-02

Group B

Content and quality

7Production data samples Upstream Must

What to extract
Real extracts, not test data, covering several periods and edge cases.
Why it matters
Real data differs from test data in ways nobody predicts.
If we do not have it
Design on guessed data. Surprises at acceptance.
From people
Source owner, and security for approval.
From systems
A read replica, a masked copy, an export.
How
Request a masked sample across time (peaks, month-end, year-end) and a set of known-bad records. Compare with test environment data.
How AI helps
Helps spot patterns once the data is masked. Limit: Never on raw sensitive data unless the environment is approved and private.
Access needed
Read-only access to a replica or a masked export, with written approval.
Precautions
Mask or pseudonymise personal data. Store only in approved places. Delete after use. Log what you took.
What can go wrong
A sample from a quiet week. Unmasked personal data on a laptop.
Backlog items
SRC-03 SRC-09

8Profiling Upstream Must

What to extract
Measured facts: row counts, blanks, distinct values, ranges, patterns, duplicates, date coverage, skew.
Why it matters
It replaces opinion with measurement.
If we do not have it
Quality and volume problems are found late.
From people
An engineer runs it; the BA reads it with the owner.
From systems
Profiling queries or a profiling tool on a replica or masked copy.
How
Run a standard profile per table. Review it with the owner: is this normal? Compare periods.
How AI helps
Writes the profiling queries, explains results in plain words and flags oddities. Limit: The facts must come from queries, not from the model's memory.
Access needed
Read-only query on a replica or a masked copy.
Precautions
Time-box and sample. Run off-peak. Profile the full history for keys and dates.
What can go wrong
Profiling masked data hides real format problems. A biased sample misleads.
Backlog items
SRC-03 PRJ-08

9Existing data quality Upstream and downstream Should

What to extract
Known problems, the rules in use today, manual fixes, who cleans what.
Why it matters
It shows what 'good' already means, and what people quietly fix.
If we do not have it
Surprises that are then blamed on the new platform.
From people
Data stewards, report owners, support.
From systems
Data quality tool results, incident tickets, error and reject tables.
How
Ask 'what do you fix by hand?'. Read the tickets. Check the error and reject tables. Compare a report with its source.
How AI helps
Summarises tickets into recurring themes. Limit: Misses problems nobody reported.
Access needed
Ticket system read, quality results read.
Precautions
Tickets can hold personal data.
What can go wrong
Teams hide known issues. Manual fixes in spreadsheets stay unseen.
Backlog items
CLN-02 CLN-04

10Volumes, growth and peaks Upstream Should

What to extract
Row counts, size, daily growth and peaks such as month-end or campaigns.
Why it matters
It sizes the design, the window and the bill.
If we do not have it
An undersized design. A cost shock. A load that overruns its window.
From people
Database administrator, operations.
From systems
Database statistics, storage metrics.
How
Read the statistics. Chart growth over 12 to 24 months. Ask about peaks.
How AI helps
Forecasts growth and explains charts. Limit: Needs real history to forecast from.
Access needed
Metrics read.
Precautions
Statistics may include test data.
What can go wrong
A peak ten times the average, found at go-live.
Backlog items
SRC-08 LND-02

Group C

Change and history

11How records change Upstream Must

What to extract
How records are inserted, updated, corrected, arrive late. Is there a modified date? Can history be rewritten?
Why it matters
It decides whether we can load only what changed.
If we do not have it
We cannot load only the changes. Silent changes. Wrong history.
From people
Source owner, source developer.
From systems
Audit columns, change logs, change data capture, update patterns in the data.
How
Ask. Inspect audit columns. Compare two extracts a day apart to see what changed. Check late arrivals.
How AI helps
Reads the update code to explain what changes records. Limit: Cannot see behaviour that is not in the code.
Access needed
Read on a replica, log read.
Precautions
Do not trust a modified date until you have checked that it is maintained.
What can go wrong
Bulk fixes that do not update the modified date.
Backlog items
SRC-04 LND-06 CLN-09

12How records are deleted Upstream Must

What to extract
Are records hard-deleted, flagged as deleted, archived or purged? Can deleted rows reappear?
Why it matters
Deletes are invisible unless you plan for them.
If we do not have it
Deleted records stay in reports for ever. Totals drift.
From people
Source owner, database administrator.
From systems
Delete flags, audit and trash tables, purge jobs, change events.
How
Ask. Look for flags. Compare full snapshots to see what disappeared. Read the purge jobs.
How AI helps
Finds purge and delete logic in code and scripts. Limit: Cannot see manual deletes.
Access needed
Read on a replica, code read.
Precautions
Know how privacy erasure requests must flow through.
What can go wrong
Hard deletes that an incremental load never sees.
Backlog items
SRC-04 LND-10

13Historical load Upstream Should

What to extract
How far back data exists, where old data lives, how formats and rules changed, how long a full load takes.
Why it matters
The first load is often the hardest.
If we do not have it
History is incomplete or inconsistent. The first load fails.
From people
Source owner, finance for the periods needed.
From systems
Archive tables, backups, old schemas.
How
Map history by period. Sample the oldest and middle periods. List schema changes. Time a trial load.
How AI helps
Compares schemas across years and lists the changes. Limit: Needs the old schemas to compare.
Access needed
Archive read.
Precautions
Old data may use different definitions. Run trial loads off-peak.
What can go wrong
A currency or code change mid-history. An archive in a different format.
Backlog items
LND-02 LND-09

14Schedules, windows and service levels Upstream Should

What to extract
When data refreshes, source batch windows, change freezes, existing service levels.
Why it matters
It decides when we may load, and what 'fresh' means today.
If we do not have it
Our load collides with the source batch. Staleness complaints.
From people
Operations, source owner.
From systems
Scheduler, calendars.
How
Read schedules. Ask about freezes such as month-end and year-end.
How AI helps
Summarises scheduler settings. Limit: Does not know the unwritten freezes.
Access needed
Scheduler read.
Precautions
Read-only.
What can go wrong
A freeze period blocks go-live.
Backlog items
LND-07 RUN-01

Group D

Downstream: the consumers

15Consumers and their needs Downstream Must

What to extract
Who uses the data, for which decision, how fresh, how detailed, and who may see what.
Why it matters
It sizes and shapes the whole platform.
If we do not have it
Wrong freshness or detail. Surprise consumers at go-live.
From people
Business owners, users, owners of downstream applications.
From systems
Report catalogue, access lists, API consumers, usage logs.
How
Build a consumer register. Interview. Read access lists and usage logs to find consumers nobody mentioned.
How AI helps
Groups usage logs into consumer groups and drafts the register. Limit: Usage is not importance.
Access needed
Usage logs read, access lists read.
Precautions
Usage logs identify people. Handle them as personal data.
What can go wrong
A finance spreadsheet that pulls data every night, unknown to IT.
Backlog items
CON-01 CON-02 CON-11

16Existing Power BI dashboards Downstream Must

What to extract
What each report shows, and the model behind it: tables, relationships, measures, filters, row-level security, refresh schedule, data sources.
Why it matters
It is the real specification of the numbers people already trust.
If we do not have it
The rebuild gives different numbers, and users reject the new platform.
From people
Report owners, report authors, power users.
From systems
Power BI service and workspaces, the report files, the dataset model through its read endpoint, the admin inventory interface, usage metrics.
How
Walk through each page with its author. Export the model: tables, relationships, measures. Read the measure formulas and the data-preparation steps. List data sources and refresh times. List slicers and security roles. Check usage. Test against known values.
How AI helps
Explains the formulas and preparation steps in plain rules, compares two reports and drafts a metric catalogue. Limit: Filter context is subtle. Verify with known numbers.
Access needed
Workspace viewer or admin rights, read access to the dataset model, the admin inventory interface. No edit rights.
Precautions
Read-only. Do not change or refresh. Files may hold embedded credentials or data. Respect row-level security and tool licence terms.
What can go wrong
Measures that use hidden filters. Manual steps in a file. Hard-coded values. Personal copies of reports.
Backlog items
SRC-12 CON-04 MNG-01

17Metric definitions in use today Downstream Must

What to extract
How each KPI is calculated today, and who owns it.
Why it matters
Two numbers with one name start every argument.
If we do not have it
Disagreement over numbers after go-live.
From people
Finance, business owners.
From systems
Report measures, spreadsheets, queries.
How
Collect each KPI from every place it is used. Put them side by side on the same data.
How AI helps
Extracts formulas from reports and queries and groups similar metrics. Limit: May merge metrics that differ in a small but important way.
Access needed
Report model read, query read.
Precautions
Show both numbers to the owner before deciding.
What can go wrong
Same name, different formula.
Backlog items
MDL-03 MNG-02

18Report and data usage Downstream Should

What to extract
Which reports and tables are actually used, by whom, how often.
Why it matters
It keeps scope honest: do not migrate what nobody uses.
If we do not have it
Migrating everything. Effort spent on dead reports.
From people
BI administrators.
From systems
Usage metrics, query logs.
How
Read 6 to 12 months of usage.
How AI helps
Summarises usage and flags what looks unused. Limit: A quarterly report looks unused in a one-month window.
Access needed
Admin usage logs read.
Precautions
Usage identifies people.
What can go wrong
A year-end report judged unused in March.
Backlog items
CON-04 PRJ-04

Reverse engineering a dashboard, layer by layer. The numbers people trust live in the formulas, not the visuals.

Group E

Rules, risk and non-functional

19Business rules hidden in code Upstream and downstream Must

What to extract
Rules in stored procedures, ETL jobs, macros, spreadsheets and scripts.
Why it matters
These are the rules nobody wrote down.
If we do not have it

PrecautionWhy
Read-only, alwaysYou are guests in someone else's system. A mistake is their incident.
Use a replica or a masked copy, not the live primaryA heavy query can slow the application for everyone.
Run big queries off-peak, with a time limit and a sampleProtects the source and your relationship with its owner.
Get access in writing, and log what you tookAuditors and owners will ask.
Keep personal data out of notes, chats and AI toolsPrivacy law applies to your working copies too.
Use only approved AI, in an approved placePublic assistants are the most common leak.

FAQ

Questions people ask

What if we cannot get any of this?

Then every missing item becomes a risk with an owner and a date, and the estimate widens accordingly. Do not fill the gap with assumptions that nobody has agreed. The 'if missing' notes on each item say what usually breaks.

Where does AI help most?

Reading large amounts of text and code: explaining old stored procedures, translating report formulas, drafting glossaries and summarising tickets. It helps least with facts about the data itself, which should be measured by queries.

Can I paste real data into an AI assistant?

Only into an AI service your organisation has approved for that data class. Otherwise give it metadata, such as column names, types and a few made-up examples.

Which items are the minimum?

The ones marked Must: meaning, relationships, keys, system flow, the type of system, a production sample, profiling, how records change and are deleted, consumers, existing dashboards, metric definitions, hidden rules and sensitive data.

Who does the extraction?

The BA leads people and artefacts, the Tech Anchor leads systems and profiling, and the PM clears access and the owners' time. See the three seats page.

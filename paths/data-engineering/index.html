Learning path

Data Engineering

You move, clean and shape data so other people can trust the numbers.

Role:Data EngAI EngLLM EngML EngSoftware EngFDE

Why this path

Every AI system is only as good as the data under it. Data engineers build that floor: pipelines that land data, tables that hold it, checks that stop bad rows, and models that give each metric one meaning.

How to use this page: 1. learn the key concepts, which are the same everywhere; 2. pick your platform; 3. work through Crawl, Walk and Run.

CrawlBeginner · 8 weeksLand a dataset, clean it in layers, and show it on a dashboard.WalkIntermediate · 3 monthsBuild pipelines that keep working: tested, modelled, governed and streaming where it matters.RunAdvanced · 6 months +Design a platform, prove its cost and correctness, and make data ready for AI.

Step 1 · the same everywhere

Key concepts

Learn these ideas first. They are the same on every cloud and with every tool; only the product names change. Each one is a short page: what it is, why it matters, an example and the common mistake.

Moving data

ETL vs ELTTwo orders for the same three steps: extract, transform, load.CrawlFull vs incremental loadsReload everything every time, or only what is new since last time.CrawlBatch vs streamingProcess data in scheduled chunks, or event by event as it happens.WalkChange data capture (CDC)Copy only what changed in a database, by reading its change log.WalkIdempotencyRunning the same thing twice gives the same result as running it once.Crawl

Storing data

Warehouse, lake and lakehouseThree ways to store data for analysis, and why most teams now use the third.CrawlFile formats: CSV, JSON, Avro, ParquetHow data is laid out in a file decides how fast and cheap it is to read.CrawlOpen table formats and ACIDDelta Lake, Apache Iceberg and Apache Hudi make files in storage behave like database tables.WalkPartitioning and clusteringArrange data so a query can skip what it does not need.WalkThe small-files problemThousands of tiny files make every query slow.WalkSeparating storage and computeKeep data in one place and rent the engines that read it only when needed.Walk

Shaping data

Medallion architecture (bronze, silver, gold)Clean data in three layers so each step is simple and you can always go back.CrawlDimensional modelling (star schema)Facts in the middle, descriptions around them: tables built for questions.WalkSlowly changing dimensionsHow to record that a customer moved city, without rewriting history.WalkNormalised vs denormalisedStore each fact once, or repeat it to make reading faster.WalkSemantic layer and metricsDefine each business number once, so dashboards and AI give the same answer.Run

Trusting data

Data quality dimensionsSix ways data goes wrong, and a check for each.CrawlData contractsA written agreement between the team that produces data and the teams that use it.WalkSchema evolutionHow a table's columns can change over time without breaking readers.WalkLineageA map of where each table and number came from, and what depends on it.WalkGovernance, access and personal dataWho owns each dataset, who may see it, and how personal data is protected.Walk

Running data

Orchestration and DAGsRun each step in the right order, on time, and retry what fails.CrawlBackfills and reprocessingRe-run a pipeline for past dates, safely.WalkFreshness and SLAsPromise how up to date data will be, then measure it.WalkWhere data costs come fromScanning, shuffling, skew and idle clusters: the four usual suspects.RunVersion control and pull requestsEvery change saved, explained and reviewed before it goes live.CrawlInfrastructure as codeThe whole environment described in files you can review and re-create.Walk

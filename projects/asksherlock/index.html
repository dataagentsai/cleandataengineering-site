1 · Purpose

AskSherlock lets a person ask a cost question in plain English and get the number, a chart and the SQL that produced it. It works over a ClickHouse cost store, as an open-source alternative to Databricks AI/BI Genie. The model only turns the question into a small validated intent from a fixed vocabulary; a semantic layer writes the SQL. It runs on a two-week time box, and the public write-up of what worked is the main deliverable.

For: Data and platform teams who want trustworthy natural-language questions over their own warehouse.

2 · Business benefits

Answers match the dashboardChat and dashboards share one set of metric definitions, so they cannot disagree.
Fewer confident wrong answersThe model cannot invent a metric or a join, which removes a whole class of errors.
Auditable resultsThe SQL is shown with every answer, so anyone can check it.
Low running costUses open-source parts and a free open-weight model on data already in the warehouse.

4 · Requirements

What it must do

  • Accept a question in plain English.
  • Turn it into an intent object naming measures, dimensions, filters and time grain from a closed vocabulary.
  • Validate the intent against a schema and refuse anything invalid before touching the database.
  • Resolve user words to real values using generated value dictionaries and synonyms.
  • Compile the intent into SQL through a semantic layer and run it.
  • Return the number, a chart chosen from the data's shape, and the SQL.

How well it must do it

  • The model never writes SQL.
  • An evaluation suite of about 120 cases runs in CI and reports intent and execution accuracy.
  • Stop rule: below 85% accuracy with clean refusals at the checkpoint, stop building and write up why.
  • Light on a laptop: the database is capped in memory and only runs while working.

9 · What you'll learn

  • Why letting a model write SQL fails on real enterprise schemas.

  • How value dictionaries stop silent empty results.
  • How to set a stop rule before you start building.

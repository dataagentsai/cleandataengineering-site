Spark Cost Agent

A Spark cost analyst agent built as a lab for agent tracing, evaluation and cost per successful task.

Active · join meAI Engineering

6 of 10 tasks done

1 · Purpose

Spark Cost Agent is a real agent that reads Delta transaction logs and Spark event logs and finds cost anti-patterns such as small files, skew and cartesian joins. The agent is not the point: everything around it is, meaning traces, metrics, evaluations, guardrails and a cost model. It is for engineers who need to run agents in production and prove they work and what they cost. It follows a ten-stage plan and builds the observability by hand so every signal is understood.

For: AI and platform engineers responsible for running, evaluating and costing agents.

2 · Business benefits

Know what each answer costsCost per successful task shows whether an agent is worth its spend, not just total tokens.
Catch quality drops earlyOnline evaluation, guardrails and alerts flag bad answers before users report them.
No vendor lock-inAll telemetry goes through one neutral collector, so backends can be added or swapped without code changes.
Safer releasesAn offline evaluation gate with a pass-rate threshold stops a worse version from merging.

4 · Requirements

What it must do

  • Answer questions about Spark and Delta cost from real logs, using four domain tools.
  • Emit a trace for every task, model call and tool call, using the standard generative-AI attribute names.
  • Price real token counts against a reference rate card, so cost stays meaningful on a free tier.
  • Capture user feedback and cheap deterministic metrics on every run.
  • Build a labelled evaluation dataset from the artifacts and from past incidents.
  • Run online checks: guardrails, a sampled model judge, injection detection and quality alerts.
  • Report coverage against an open AI assurance catalog.

How well it must do it

  • No agent framework: the loop is hand-written so every span is owned code.
  • Works without an API key for everything except asking the agent.
  • Offline test suite runs with no network.
  • Light enough for an 8 GB laptop; hosted free tiers used where local tools are too heavy.
  • Model provider switch is a configuration change, never a code change.

5 · Architecture, very high level

Also: Agent loop → Domain tools: tool call · Cost model → Trace and metric backends: shadow cost · Evaluation suite → Agent loop: test questions · Online guard → Agent loop: checks on live answers

9 · What you'll learn

  • How to instrument an agent by hand with standard trace names.
  • Why a collector between app and backends keeps you vendor-neutral.
  • How to compute cost per successful task, not just cost per call.
  • Offline versus online evaluation, and when a model judge can be trusted.
  • Why counting only added files in a Delta log gives the wrong answer.

Level-up questions

  • How much agreement with humans does a judge need before you trust it?
  • What sampling rate catches quality drops without paying for every check?
  • Which optimisation cuts cost per success most: caching, routing or trimming?

Conversation UI on Data

A specification for chat-with-your-data where the model picks certified metrics and never writes SQL.

1 · Purpose

This is a specification, not an implementation: the right architecture for asking questions of data in plain English. It covers two settings, data governed in Unity Catalog on Databricks, and data in PostgreSQL or ClickHouse on a virtual machine. Its core rule is that the model selects a certified metric and dimensions, and a deterministic engine writes the query. It is for teams planning a conversational analytics product who want answers that match their dashboards.

For: Data architects, analytics engineers and product teams planning natural-language analytics.

2 · Business benefits

Trustworthy numbersChat and dashboards read the same semantic layer, so they always give the same answer.
Less reworkWriting the metric contract first stops gold tables being built in the wrong shape.
Clear tool choiceThe spec explains which semantic layer fits each setting and why.
Lower risk at launchShipping dashboards before chat exposes definition bugs to a forgiving audience first.

4 · Requirements

What it must do

  • Define what a right answer means in testable terms.
  • Give a layered reference architecture from raw data to chat.
  • Correct four common medallion assumptions, such as keeping gold atomic rather than aggregated.
  • List what a semantic model must declare: grain, measures, dimensions, join paths, synonyms and owners.
  • Map the architecture to each track's technology and compare semantic layer options.
  • Set the order of work, from metric contract to golden questions to dashboards to chat.

How well it must do it

  • No code is generated in this repository by design.
  • Every claim about accuracy cites a public benchmark or source.
  • Answers must be fast and cheap enough to ask a hundred times a day.
  • Governance: access rules apply the same way in chat and dashboards.
